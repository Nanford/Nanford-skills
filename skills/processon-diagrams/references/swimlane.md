# 业务流程泳道图规范（`diagram: "swimlane"`）

适用于跨部门业务流程图、审批流转图、端到端服务交付流程、SOP 跨职能流程图。

参考成品：`examples/business-swimlane.svg`（由 `examples/business-swimlane.json` 生成）。

---

## JSON 模型

```json
{
  "diagram": "swimlane",
  "title": "商务业务流程",
  "themeName": "processon-gray",
  "canvas": { "w": 1160 },
  "lanes": ["客户", "商务", "销支", "公司内部协同", "相关文档"],
  "nodes": [
    { "id": "start", "lane": "客户", "row": 0, "type": "start", "label": "开始" },
    { "id": "intent", "lane": "客户", "row": 1, "label": "推广意向" },
    { "id": "intro", "lane": "商务", "row": 1, "label": "介绍方案" },
    { "id": "doc_ppt", "lane": "相关文档", "row": 1, "type": "document", "label": "业务介绍PPT" },
    { "id": "agree", "lane": "客户", "row": 2, "type": "decision", "label": "是否同意\n方案" },
    { "id": "draft", "lane": "商务", "row": 3, "label": "制定合同\n提交场景" }
  ],
  "edges": [
    { "from": "start", "to": "intent" },
    { "from": "intent", "to": "intro" },
    { "from": "intro", "to": "agree" },
    { "from": "agree", "to": "intent", "label": "否" },
    { "from": "agree", "to": "draft", "label": "是" }
  ]
}
```

---

## 字段说明

### 顶层字段

| 字段 | 必填 | 说明 |
|------|------|------|
| `diagram` | 是 | 固定填 `"swimlane"` |
| `title` | 建议 | 顶部流程总标题栏文字（默认左对齐，可设 `"titleAlign": "center"` 居中） |
| `themeName` | 否 | 默认 `processon-gray`（复刻 ProcessOn 经典黑白灰商务泳道风格）；可选 `processon-teal` / `processon-blue` / `processon-green` / `processon-orange` |
| `canvas.w` | 否 | 画布宽度，默认 `1160`；泳道超过 5 列建议 `1320–1560`。画布高度自动计算 |
| `rowGap` | 否 | 行间通道高度，默认 `40`；若有多条回退/分支标注线可适当调大到 `48` |
| `lanes` | 是 | 角色/部门泳道列表（从左到右）。可直接写字符串数组，也可写对象 `{"id": "x", "title": "角色名", "width": 1.2, "fill": "#..."}` 自定义相对列宽或表头底色。可将最后一列设为 `"相关文档"` 放置独立交付物 |
| `nodes` | 是 | 流程节点列表 |
| `edges` | 否 | 节点间流向连线（也兼容 `connections` 字段名） |

### 节点字段（`nodes[]`）

| 字段 | 必填 | 说明 |
|------|------|------|
| `id` | 建议 | 节点唯一标识，供 `edges` 引用 |
| `lane` | 是 | 所属泳道（可填泳道标题、`id` 或从 `0` 开始的列索引） |
| `row` | 建议 | 所在行号（从 `0` 开始，自上而下排布）。显式填写可精确控制上下对齐与行间留白；省略时脚本会按连线拓扑顺序自动分配行号 |
| `label` | 是 | 节点文字，支持用 `\n` 手动换行，超长时也会按列宽自动换行 |
| `type` | 否 | 图元类型，默认 `"process"`，见下表 |
| `variant` | 否 | `"highlight"`（主题高亮底色 + 加粗）或 `"external"`（虚线边框，用于外部角色/系统） |
| `fill` | 否 | 覆盖节点填充色（如 `"#FFF7E6"`） |

**支持的业务流程图元（`nodes[].type`）：**

| `type` | 视觉形状 | 适用语义 |
|--------|---------|---------|
| `start` / `end` | 胶囊起止框（圆角矩形） | 流程开始、流程结束 |
| `process`（默认） | 标准直角矩形 | 业务动作、审批节点、操作步骤 |
| `decision` | 菱形判断框 | 条件分支（配合 `"是"` / `"否"` 连线标注） |
| `document` | 波浪底文档框 | 相关文档、协议、表单、PPT 等交付产物（常放在最右侧 `相关文档` 泳道） |
| `subflow` | 双竖线子流程框 | 独立子流程、ERP/外部系统封装流程 |
| `data` | 平行四边形 | 表单、单据、数据输入/输出 |

### 连线字段（`edges[]`）

| 字段 | 必填 | 说明 |
|------|------|------|
| `from` / `to` | 是 | 起点与终点节点 `id` |
| `label` | 否 | 条件或动作标注（如 `"是"`、`"否"`、`"退回修改"`），自动带白底断线效果 |
| `dashed` | 否 | `true` 表示虚线（用于异步通知、外部协作、文档引用） |
| `fromPort` / `toPort` | 否 | 可选强制端口：`top` / `bottom` / `left` / `right`；默认由避障路由引擎自动选最优正交走线 |
| `labelPos` | 否 | 标注在线段上的位置比例（`0.0 ~ 1.0`，默认 `0.5` 居中），当两条线交汇附近有文字时可微调（如 `0.35` 或 `0.65`） |

## 排布与走线最佳实践

1. **同一列不要塞太满**：同一行的相邻节点之间最好保持清晰因果顺序，主流程自上而下逐行推进，避免所有节点挤在 2–3 行里导致大量折线交叉。
2. **判断节点留好分支空间**：`decision` 菱形的 `"是"` 分支通常向下进入下一行，`"否"` 分支回到上一步或水平指向同行的“修改/退回”节点，路由引擎会自动走直线或行间通道，不会压盖其他节点。
3. **相关文档单独放最右侧泳道**：像 ProcessOn 经典模板一样，将 `"相关文档"` 作为最右侧泳道，把 `type: "document"` 节点放在与业务步骤相同的 `row` 上，无需画多余连线即可一目了然。

## 泳道图专属自检

在完成 `references/style-guide.md` 通用自检外，额外确认：

- [ ] 每个泳道标题清晰，节点归属角色准确，无错位到其他泳道
- [ ] 所有判断菱形至少有两条出口（如 `"是"` / `"否"`）且标注无遮挡
- [ ] 没有连线穿越无关节点内部；若某条自动走线偏绕，微调节点 `row` 或加 `fromPort`/`toPort`
- [ ] 流程起点、终点与主干流向清晰，从上到下阅读顺畅
