# 文案写作范式

## 五点描述的结构

每条采用利益点前置加特征支撑的结构。买家在移动端只扫每条的前几个词，把结论放在最前面。

反面例子：Made of high quality aluminum alloy material which is durable and can be used for a long time.

正面结构：一个短的大写抓手短语，冒号，然后是具体的利益加支撑事实。抓手短语控制在两到四个词，全大写但不要整条大写。

五条之间要覆盖不同维度，对应 listing.json 里的 dimension 字段：核心功能、材质工艺、使用场景、规格兼容、配件售后。五条都在讲材质是最常见的失败模式。

单条长度控制在站点上限的百分之八十以内，留出余量。写满上限的文案在移动端会被折叠，反而看不到。

## Amazon 美国站五点描述

目标是从已确认的标题关键词、规格资料和可观察图片事实中自动提炼 3 至 5 个核心卖点，再扩写为严格 5 条美国英语文案。采用以下规则：

1. 每条使用 `卖点短语 - 说明文案`。卖点短语直接点明差异，连字符后的说明以 `Enjoy`、`Experience`、`Discover`、`Get` 等有力动词开头；不要为了套用动词破坏自然表达。
2. 每条优先控制在 20 至 25 个英文单词，并保持在站点字符上限以内。20 至 25 个单词与固定字符数并不总能同时满足，因此以自然、准确和单词数为主，不机械填充。
3. 每条自然包含 1 至 2 个相关搜索词，并说明技术特征怎样转化为用户利益或具体使用场景；不要堆砌同义关键词。
4. 五条分别覆盖核心功能、舒适或材质、连接或兼容、续航或效率、场景或配件等不同维度。没有对应事实时换用其他已确认维度，不凑数。
5. 可以指出相对常见痛点，例如减少频繁充电或便于多设备切换，但不得点名竞品、贬损竞品或声称没有证据的领先优势。
6. 产品标题中的明确参数可作为用户提供的来源事实。图片只补充可直接观察的外观、结构、材质表现和场景线索；容量、尺寸、协议版本、续航、距离、认证、防护等级等硬参数不可从图片猜测。
7. 不得把“合理推断”写成公开事实。影响成稿的推断进入待确认清单；无法确认时改写为不依赖该参数的利益表达。

用户只要求独立生成五点描述时，仅返回以下 JSON 对象，不加 Markdown 或解释：

```json
{
  "bullet_points": ["Point1", "Point2", "Point3", "Point4", "Point5"],
  "language": "en-US"
}
```

`bullet_points` 必须且只能有 5 条，`language` 使用 BCP 47 语言代码。在完整生产链中，把同样的 5 条内容写入 `copy.json.bullets`，不要另建第二份事实源。

## 标题的结构

Amazon 的结构是品牌加核心产品词加关键属性加适用范围加规格。核心产品词要用买家实际搜索的说法，不是内部叫法。

eBay 只有 80 字符，必须重写而不是截断。保留核心产品词和最重要的两三个属性。

三类内容不要进标题：促销信息、平台名称、无关关键词堆砌。

## 关键词嵌入

关键词要长在句子里，不是并列堆砌。判断标准是把关键词去掉后句子是否仍然通顺——如果去掉后句子垮掉，说明嵌得自然；如果去掉后句子毫无变化，说明是硬塞的。

后台搜索词不要重复标题和五点里已有的词，Amazon 的索引不会因为重复而加权。用来放同义词、拼写变体、场景词。

## 多语言本地化

不要先写英文再翻译。把结构化卖点加站点规则一起送进去，直接生成目标语言原文。翻译腔在德语和日语里特别明显，本地卖家一眼能看出来。

硬性转换项：英制公制换算并按当地习惯标注、尺码体系映射、插头与电压说明、日期与数字格式。这些在 locale 文件里有具体规则。

场景引用要本地化。美国站的感恩节场景不能直接搬到德国站，日本站的通勤场景和美国站的通勤场景想象完全不同。

## 待确认属性的处理

listing.json 里标了 needs_confirmation 的属性，默认不写进文案。如果这条对转化很关键（充电宝不写容量几乎没法卖），向用户要，不要自己填。

被排除的卖点要写进 copy.json 的 excluded_points，让用户知道补齐后能拿回什么。
