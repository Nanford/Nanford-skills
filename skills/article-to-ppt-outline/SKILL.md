# Article to PPT Generator

将输入文章转化为结构化 PPT 大纲，每页含【页型标识】【视觉排版建议】【文案内容】【讲师逐字稿】四个模块。

输出格式已与下游生成技能 `text-to-ppt-pro` 的 13 种页型系统对齐，可直接用于程序化 .pptx 生成。

## 输入规范

- `source_text`（必填）：原始参考资料（纯文本、Markdown 等格式均可）
- `target_pages`（选填）：期望总页数，默认根据内容体量自动评估（通常 10–30 页）
- `audience`（选填）：目标听众特征（如技术人员、高管、销售），默认通用职场人群
- `theme`（选填）：主题风格预设，可选值见下表，默认根据受众和场景自动推断

### 主题预设速查

| 标识 | 风格 | 适合场景 |
|------|------|---------|
| `dark_tech` | 深色科技感 | AI 培训、技术方案、产品演示 |
| `business_blue` | 商务蓝白 | 项目汇报、售前提案、甲方汇报 |
| `mckinsey_clean` | 麦肯锡简洁风 | 管理复盘、策略汇报、领导简报 |
| `warm_exec` | 暖灰高管汇报 | 董事会汇报、经营分析、年度总结 |

---

## 工作流程

严格按顺序执行以下 5 步：

**步骤 1：知识原子化抽取**
完整阅读 source_text，滤除冗余过渡句和修饰语，将长文本拆解为相互独立、完全穷尽的原子知识点。

**步骤 2：规划宏观骨架**
根据知识点的逻辑关系，构建 PPT 整体架构（如：痛点引入 → 核心概念 → 落地实操 → 总结行动）。确保逻辑递进，控制单页信息密度。

**步骤 3：逐页定型 — 先选页型，再填内容**

这是与下游生成层对接的关键步骤。**每一页必须先从 13 种标准页型中选定 `type`，再决定内容和排版。**

页型选择前问自己：这页是为了让人"听懂"还是"看懂"？建立认知还是推动决策？

**步骤 4：逐页精细扩写**
按照骨架逐页生成内容，每页必须包含四个固定模块（见输出格式）。

**步骤 5：合规自检**
检查屏幕文案是否超字数、逐字稿是否口语化、是否存在原文中不存在的幻觉信息、页型标识是否准确。

## 13 种标准页型

以下页型标识是下游生成层的硬接口，**必须使用这些标识名，不可自创。**

| 标识 | 名称 | 关键词 / 使用场景 |
|------|------|------------------|
| `cover` | 封面页 | 大标题、定调、极简，开篇第一页 |
| `intro` | 导读页 | 为什么讲、解决什么问题、拉齐预期 |
| `toc` | 目录页 | 编号+标题+章节预览，3–6 章节 |
| `transition` | 章节过渡页 | 极简大字、切换模块、标记章节边界 |
| `four-grid` | 四宫格认知页 | 概念分层、2×2 卡片、象限分析 |
| `comparison` | 对比页 | 左右对照、误区vs正解、方案PK |
| `process` | 流程页 | 步骤链路、审批流、业务流、机制 |
| `method` | 方法步骤页 | SOP、编号步骤、实施路径、操作指南 |
| `framework` | 框架模型页 | 同心圆、金字塔、分层体系、能力地图 |
| `case-study` | 案例页 | 问题-动作-结果、场景说明 |
| `data` | 数据结论页 | 经营数据、KPI、结论在上+图表支撑 |
| `summary` | 总结页 | 3 个结论或行动建议、模块收束 |
| `closing` | 致谢页 | 感谢语、Q&A 提示、联系方式 |

### 常见自然语言 → 页型映射

| 你在原文中看到的内容特征 | 应选页型 |
|------------------------|---------|
| 开篇破题、课程/汇报标题 | `cover` |
| "为什么""背景""痛点""现状" | `intro` |
| 文章目录、纲要、要点预览 | `toc` |
| 章节分隔、段落之间的转场 | `transition` |
| 四个维度、2×2 矩阵、四象限 | `four-grid` |
| "对比""vs""区别""误区与正解" | `comparison` |
| "流程""步骤""先…再…然后" | `process` |
| "怎么做""方法""操作""SOP" | `method` |
| "架构""模型""框架""体系" | `framework` |
| "案例""实践""客户故事""举例" | `case-study` |
| 百分比、增长率、KPI、图表描述 | `data` |
| "总结""小结""行动建议""记住" | `summary` |
| 文章结尾、致谢、联系方式 | `closing` |

## 输出格式

### 全局元信息（输出在最开头）

```
## 全局信息

- **主题**：[PPT 主题名称]
- **受众**：[目标听众]
- **主题预设**：[dark_tech / business_blue / mckinsey_clean / warm_exec]
- **总页数**：[N 页]
- **骨架结构**：[如：痛点引入(2页) → 核心概念(5页) → 落地实操(8页) → 总结行动(3页)]
```

### 逐页内容（每页严格使用以下模板）

```
### 第 X 页：[单页主标题]

**【页型】** `type标识`

**【视觉与排版建议】**
* **排版结构**：[具体到页型支持的子结构，如"横向流程 4 步"、"左右对比 各3条"、"2×2 卡片"]
* **配图/图标建议**：[具体描述需要的视觉元素]

**【文案内容】**
* [小标题 1]：[提炼后的极简短句，不超过 15 个字]
* [小标题 2]：[提炼后的极简短句]
（注：本部分内容必须高度精简，能用词的不用句，能用表的不用段落）

**【讲师逐字稿】**

> "[口语化表达。将书面语转化为对话口吻，有起承转合，适当加入'大家看屏幕'、'举个例子'等连接词。字数控制在演讲 1–2 分钟的体量。]"
```

### 各页型的文案内容格式要求

不同页型的【文案内容】模块应匹配其结构特征：

**`cover` 封面页：**
```
* **主标题**：[结论式标题，不是课题名]
* **副标题**：[一句话说明用途或核心价值]
* **页脚**：[讲者 / 日期 / 单位]
```

**`comparison` 对比页：**
```
* **左栏标题**：[问题/旧方式/误区]
  - [对比项 1]
  - [对比项 2]
  - [对比项 3]
* **右栏标题**：[目标/新方式/正解]
  - [对应项 1]
  - [对应项 2]
  - [对应项 3]
```

**`four-grid` 四宫格认知页：**
```
* **格 1 标题**：[关键词] — [一句话定义]
* **格 2 标题**：[关键词] — [一句话定义]
* **格 3 标题**：[关键词] — [一句话定义]
* **格 4 标题**：[关键词] — [一句话定义]
```

**`process` 流程页：**
```
* **步骤 1**：[关键词，2–5 字]
* **步骤 2**：[关键词]
* **步骤 3**：[关键词]
* **步骤 N**：[关键词]
（步骤数建议 3–6 步，超过 6 步考虑拆页或改用纵向流程）
```

**`method` 方法步骤页：**
```
* **01 [步骤名]**：[一句话说明]
* **02 [步骤名]**：[一句话说明]
* **03 [步骤名]**：[一句话说明]
```

**`case-study` 案例页：**
```
* **问题/背景**：[面临什么挑战]
* **动作/做法**：[做了什么]
* **结果/价值**：[取得什么成果，尽量量化]
```

**`data` 数据结论页：**
```
* **核心结论**：[一句话结论，放在最醒目位置]
* **关键数字**：[XX%、XX万、XX倍等]
* **图表类型建议**：[柱状图/折线图/饼图/数据卡片]
```

其他页型（`intro`、`toc`、`transition`、`framework`、`summary`、`closing`）使用通用格式即可。

## 典型场景的页型编排参考

### 培训课件
```
cover → intro → toc → transition → four-grid/framework → method × N → case-study → summary → closing
```

### 项目汇报
```
cover → intro(执行摘要) → toc → transition → data(阶段成果) → comparison(风险对比) → process(计划) → summary → closing
```

### 售前方案
```
cover → intro(行业痛点) → comparison(现状vs目标) → framework(方案架构) → case-study × N → process(实施路径) → data(价值数据) → summary → closing
```

### 知识型演示
```
cover → intro → toc → [transition → framework/four-grid → method] × N → case-study → summary → closing
```

## 约束规则

- **严禁照搬原文**：禁止将大段原文直接复制到【文案内容】，屏幕文案必须经过压缩和结构化
- **严禁缺漏逐字稿**：每一页都必须有【讲师逐字稿】
- **严禁信息幻觉**：只能基于 source_text 包含的信息提炼，不可编造原文未提及的数据或专业术语
- **严禁自创页型**：`type` 标识必须使用上述 13 种之一，不可自创
- **语言风格**：输出默认使用简体中文；逐字稿需体现专业、自信且互动的讲师状态
- **信息密度控制**：单页屏幕文案不超过 80 字（不含标题），超出部分下沉到逐字稿
