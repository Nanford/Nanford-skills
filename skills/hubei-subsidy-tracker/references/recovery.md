# 中断恢复与升级

## 恢复入口

先运行 `init_setup.py --status --json`，检查 `next_action`、`last_run.json` 及最近日志。凭证或状态文件损坏时保留原件，修复具体字段，不清空企业资料或发送记录。

| 情况 | 恢复动作 |
|---|---|
| 缺 Python 或依赖 | 核对可用解释器与安装权限；依赖失败停止后续安装，不显示完成 |
| 企业资料为空或缺基础字段 | 补充名称、地区、行业后继续；财务和资质逐项由政策触发补充 |
| Excel 正被占用 | 关闭对应文件后重试；已发送消息不重新发，只补写状态 |
| 单个政策源失败 | 保留其余结果，修复网络或解析器后重新采集，报告覆盖不完整 |
| 表格 ID、字段或组织改变 | 刷新快照并重新验证目标；旧回执不能证明新目标可用 |
| 同名通知人 | 列出可核验的组织身份供确认；未确认不猜选、不改发默认人 |
| daily.lock 残留 | 读取 PID，确认原任务已结束；仅删除该客户目录下的锁后重跑 |
| 任务存在但无执行记录 | 核对解释器、工作路径、数据目录、账号权限和电脑在线状态，再试运行 |

## 发送结果不明

```text
python scripts/notification_ledger.py status
```

`sending` 表示已预留发送，但尚未持久记录业务成功；可能未发出，也可能已送达。先查平台业务记录或与收件人核对，不直接重发。

确认已送达：

```text
python scripts/notification_ledger.py resolve --key <政策ID|企业名称> --status sent --reference <实际核对依据>
```

确认未送达：

```text
python scripts/notification_ledger.py resolve --key <政策ID|企业名称> --status pending --reference <实际核对依据>
```

参数包含 `|` 时由结构化参数传递或按当前 shell 正确引用，不能直接拼接未引用的命令。只有 `sending` 允许核对；成功记录不得重置为待发送。

已标记 `sent` 而表格未回写时，只补写本地和远端通知状态。运行 `notification_ledger.py repair-local` 可补写台账成功项的本地通知状态，不发送消息。钉钉重新执行原成功结果的 `mark` 生成远端回写；飞书执行匹配表同步。不得为了补写表格再次发送消息。

## 升级与迁移

程序和运行数据分开管理。升级前备份所选客户的配置、数据及通知台账，不能用分发包的示例配置替换真实配置。SQLite 台账备份在任务停止且连接关闭后执行；运行中不得只复制数据库主文件。

新版本解压到新目录时继续指定原 `SUBSIDY_DATA_DIR` 与 `SUBSIDY_CONFIG_FILE`，重新生成本机任务入口，检查旧任务后再切换。数据目录或平台配置变化会要求重新验证相关步骤，成功通知台账仍保留。

旧版若将配置放在 `scripts/config.env`，升级时通过 `SUBSIDY_CONFIG_FILE` 显式指定该文件，或在备份后迁移到根目录；新版不再从多个位置叠加配置，避免体检与执行使用不同凭证。

迁移验收至少包括：既有企业可读取、人工处理状态保留、已通知项目不会再次进入发送、当前有效未通知结果仍能生成、调度任务指向正确版本。旧运行日志与回执不作为新机器的实际执行证明。
