# 日常运行

## 本地与飞书

运行 `python scripts/run_daily.py`。本地模式采集后匹配；飞书模式在匹配前拉取企业档案，匹配后同步。只有通知偏好已开启且收件范围验证仍有效时，日常入口才调用飞书通知。

`--local-only` 只采集和使用本地档案匹配，不读写平台、不发送通知；在飞书或钉钉模式使用时，应向客户注明档案为本地快照并核对更新时间。

`daily.lock` 避免本地入口重叠运行，`collection_report.json` 记录各源结果，`last_run.json` 记录完成步骤与结果。某个源失败仍保留其它来源的采集成果，但日常入口停止后续自动外发并报告结果不完整。

零命中与请求失败分别报告；零命中可能是无符合政策，也可能是页面改版，不把零命中视为已证实没有政策。主体门槛和附件仍需复核。

## 查询与档案更新

- 当天新增：读取 `digest_latest.md`，附报告日期与采集异常。
- 某企业能报什么：读取当前有效政策和匹配结果；若企业资料有更新先重新匹配。列出依据、缺口、原文和下一步。
- 企业补充资料：核对所属年度与单位，更新所选模式的事实源后再匹配。不要求客户重复提交已有资料。
- 申报核对草稿：运行 `fill_draft.py --policy <政策ID或标题> --enterprise <企业名称> --out <绝对目录>`；只有已知字段参与填报，不声称已解析并回填附件模板。

## 通知规则

日报仅统计当天采集；通知按当前有效、结论为匹配、可通知、尚未成功发送筛选，不受采集日期限制。首次启用前预览存量结果和收件范围，获得该范围的发送授权。

同一政策与企业的成功通知由表格状态和 `notifications.sqlite` 双重保护。重新解析或补档不重置已成功通知。飞书每轮最多包含 50 条，只有实际包含的记录被标记发送，剩余记录下轮继续。

发送前写入 `sending` 预留，业务成功后立即写入 `sent`，再回写表格。超时或进程中断可能留下 `sending`，须按恢复流程核对；不承诺跨网络与平台的绝对恰好一次投递。

钉钉每条计划先执行 `reserve_argv`，再由宿主发卡片或文本，每条成功立即保存结果并执行 `mark`。卡片创建成功但更新失败时先使用已有业务 ID 恢复更新，不直接另发卡片。

## 定时与运行反馈

本地与飞书使用安装生成的 `run_daily.bat`，日志位于数据目录的 `logs/`。钉钉执行专用宿主步骤，保存同一数据目录的状态与回执。

只向明确配置的运维负责人报告运行异常，不借用任意企业负责人作为默认收件人。任务注册与历史回执不能替代本次成功执行；对外报告以本次日志及平台结果为准。
