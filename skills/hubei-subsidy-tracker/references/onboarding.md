# 首次引导与接入验收

## 六步交付

| 步骤 | 智能体动作 | 客户操作 | 通过条件 |
|---|---|---|---|
| 环境检查 | 探测 Python、文件读写和实际宿主能力 | 必要时登录或安装解释器 | 所需能力可调用 |
| 使用方式 | 识别已有模式，推荐可用路径 | 确认本地、飞书或钉钉 | 模式与数据位置固定 |
| 企业档案 | 创建空白档案或读取已有资料，核对单位与年度 | 确认基础事实 | 至少一家企业有名称、地区与行业，无重名冲突 |
| 协作连接 | 绑定或创建表格，检查字段与接收身份 | 必要授权及目标确认 | 实际读写与通知目标验证通过 |
| 首次结果 | 采集、匹配、解释依据与资料缺口 | 查看结果并补充关键资料 | 本次采集报告和匹配结果可读取 |
| 日常运行 | 保存偏好、登记任务并验证一次执行 | 确认时间与通知范围 | 所选功能均有成功证据 |

日常查询不必等待可选的通知或定时接入完成。每轮只追问会影响下一步的缺失信息，已有选择不重复问。

## 安装

以下命令均相对于 Skill 根目录；实际执行使用已定位的绝对脚本路径。

```text
python scripts/init_setup.py --status --json
python scripts/install.py --mode local --skip-first-run
python scripts/init_setup.py --status --json --checkpoint
```

- 安装需要 Python 3.10+，依赖见 `requirements.txt`。受限环境由智能体提供匹配的安装方式，不循环重试同一个失败命令。已有依赖可传 `--skip-deps`。
- `--mode` 省略时保留已有模式，新安装默认本地；飞书用 `--mode feishu`，钉钉用 `--mode dingtalk`。
- 默认安装不创建定时任务；`--skip-first-run` 只准备组件，稍后由智能体运行首次采集。没有企业数据时能先查看政策。
- 安装返回 2 时查看当前待办或错误：档案未填、验证未做与依赖安装失败是不同问题。不要把“待引导”当成需要反复重新安装。
- 独立客户数据目录在第一次调用前设置 `SUBSIDY_DATA_DIR`，独立配置使用 `SUBSIDY_CONFIG_FILE`；后续命令与调度环境必须保持一致。

## 企业档案

先核对企业名称、注册地区与主营行业。未知资质留空或标记待确认，不把未提供解释为没有资质。金额使用万元，记录数据年度；缺少年度时不得代替政策指定年度。

已有 Excel 读取首张“企业档案”表，示例表不得参与匹配。已有营业执照、财报和证书可以由具备文档能力的智能体提取，但客户确认前不作为已核验事实。只补充真实提供的信息。

同名企业先核对信用代码，不能以新增重复行解决冲突。通知人仅在启用对应通知功能时必需。财务与资质缺口由具体政策触发追问，并注明政策、字段、单位和所属年度。

## 三种模式

### 本地

维护 `enterprises.xlsx`，资料原件保留在数据目录。运行：

```text
python scripts/run_daily.py --local-only
```

成功采集与匹配会自动记录回执。没有档案时完成采集并保留匹配待办；原文或附件不足时结果进入复核。

### 飞书

1. 绑定已有多维表格，或在授权范围内创建“政策清单、企业档案、匹配结果”三表，字段见 `fields.md`。
2. 自建应用需具备表格读写权限并成为目标表协作者。凭证通过本地配置输入，不把密钥复制到报告或回执。
3. 在现有配置中补齐 `FEISHU_APP_ID`、`FEISHU_APP_SECRET`、`FEISHU_BASE_URL`，不要用示例文件覆盖已有配置；确认 `SKILL_MODE=feishu`。
4. 执行 `feishu_sync.py --check` 核验连接，再对明确选定的真实记录完成受控写入并读回，保存 `tables` 回执。仅 `--check` 成功不代表写权限已验证。
5. 企业档案以飞书维护表为准，先 `--pull` 再匹配。群通知仅发往有权查看这些企业结果的群，先预览收件范围、存量数量及内容。
6. 首次先执行 `feishu_sync.py --notify-preview --notify-limit 1` 预览一条，确认后使用 `feishu_sync.py --notify --notify-limit 1` 受控测试。只有业务成功并核对目标群后记录 `notification` 回执；无需通知时保持未启用。正式开启前另用默认批次预览存量数量，明确后续自动通知范围。

### 千问办公与钉钉

继续 `dingtalk_qwen.md`。宿主不可用时保留已完成的本地能力与平台待办，不尝试在 Python 子进程里调用宿主连接器。

## 偏好和验证回执

客户明确选定后执行：

```text
python scripts/init_setup.py --notifications on
python scripts/init_setup.py --schedule on
```

这两项只保存选择，不代表通知已发送或定时任务已创建。关闭偏好用 `off`；停止已存在的外部定时任务还需在对应调度平台停用并核对，不仅修改本地标记。

外部验证回执由执行验证的智能体保存为本地 JSON，字段如下：

```json
{
  "success": true,
  "context": "验证前 status --json 输出的 contexts 对应步骤值",
  "observed_at": "实际验证时间，ISO 8601 格式并包含时区",
  "reference": "实际平台业务回执编号或本地验证报告相对路径"
}
```

上例为字段说明，不得原样提交或编造成功回执。`tables` 必须完成读写后读回；`notification` 必须完成目标核验与实际业务成功；`schedule` 必须核验任务存在、时间正确且最近一次实际运行成功。

```text
python scripts/init_setup.py --record tables --evidence <回执文件绝对路径>
python scripts/init_setup.py --record notification --evidence <回执文件绝对路径>
python scripts/init_setup.py --record schedule --evidence <回执文件绝对路径>
python scripts/init_setup.py --status --json --checkpoint
```

回执必须在 24 小时内记录，且上下文未变化；仅持久保留成功状态、时间、摘要与引用，不保存凭证或完整平台响应。既有回执反映上次验证，不替代平台实时状态；宣布启用前再次核对连接器与调度任务。

钉钉宿主分步执行的采集、匹配也可按同样方式记录 `collection`、`matching`，必须先检查本次采集报告和真实输出，且在文件更新后获取上下文摘要。

## 定时运行

本地或飞书在客户明确启用后执行：

```text
python scripts/install.py --enable-task --time 09:00 --skip-deps --skip-first-run
```

Windows 任务名按客户数据目录派生，已有相同路径和时间的任务复用，不强制覆盖冲突任务。登记成功后核验 `schedule_registration.json` 指向的任务，并在用户授权范围内运行一次，检查退出码和本次 `last_run.json` 后记录 `schedule` 回执。

旧版固定名称 `HubeiSubsidyDaily` 可能仍存在。升级时先检查其目标路径，显式停用同一客户的旧任务后再启用新任务，避免两套任务并行。不同客户的任务不改动。

钉钉使用千问办公定时任务，须验证调度环境能访问同一客户数据目录与连接器。本地目录不能被云端任务访问时，不宣称定时已完成；改用可访问相同数据的受支持环境。

## 接入结果

分别展示已验证的政策查询、企业匹配、通知和定时能力，附企业数量、报告入口、下一次运行时间及剩余待办。未启用的功能不写成故障，未验证的能力不写成可用。
