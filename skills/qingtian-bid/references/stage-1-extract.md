# 阶段 1 提取细则

阶段 0 完成（格式已确认）后读。目标是把登记的每个来源都转成可以逐行引用的文本，提取报告全部通过，来源在提取后没被替换。提取不过，后面的解标全部没有依据，所以这里的硬停不能绕过（R9）。

命令里的 `<skill目录>` 是本 Skill 所在的目录（SKILL.md 所在目录）。路径可能带空格，引号要留。命令在哪个目录运行都可以。所有材料只在本机处理，不外传，不调用在线 OCR（R26）。

## 一、来源与类别

开工时 `prepare_project.py` 已把来源登记进 `project-state.json` 的 `sources`，每条是 `{"path", "kind"}`，路径相对项目目录。类别三种：

| 类别 | 放在 | 包括 | 提取不出文字时 |
|---|---|---|---|
| tender（招标文件） | `source/` | 招标文件正文、补遗、澄清、答疑、工程量清单 | 硬停（R9） |
| drawing（图纸） | `source/drawings/` | 用户声明为图纸的文件（含 DWG、DXF） | 记为 `drawing`，按图号人工读，不硬停 |
| sample（响应样本） | `source/response-samples/` | 历史中标施组等（R25） | 硬停（R9） |

图纸只能由用户声明（决策 2A）。开工时用 `prepare_project.py --drawing <文件>`，开工后用第三节的 `--add-source --kind drawing`。不得因为文件名像图纸、或者提取不出字，就自己把它改登成图纸。招标文件正文、补遗、工程量清单一律不得登记为图纸：它们提取不出字就是扫描件，按第四节硬停。

## 二、提取

```powershell
python -X utf8 "<skill目录>/scripts/project_status.py" <项目目录> --start 1
python -X utf8 "<skill目录>/scripts/extract_text.py" --project <项目目录>
```

`--project` 按 `sources` 整批提取，每次都重提全部来源，不做增量。产出：

| 路径 | 内容 |
|---|---|
| `analysis/extracted-text/<文件名>.txt` | 每个来源一份文本。PDF 每页前有 `--- 第 N 页 ---`，xlsx、xls 每张表前有 `--- 工作表：<表名> ---`。同名不同扩展名的来源自动加后缀，不互相覆盖 |
| `analysis/extraction-report.json`、`.md` | 每个来源的类别、状态、字数、页数、原因和 sha256 |

支持的格式：PDF、DOCX、XLSX、XLS、TXT、MD、CSV，图纸另有 DWG、DXF；老式 `.doc` 要靠本机的 Word、WPS 或 LibreOffice 转换，都没有时判失败，请用户另存为 `.docx`。

- 工程量清单用 `.xlsx` 原样提取，单元格之间用制表符分隔，不需要另装依赖。单元格里的换行（如多行的项目特征描述）压成空格，一行清单在提取文本里也是一行。
- 老格式 `.xls`（合肥的工程量清单、最高投标限价大多是这种）先复制到临时目录，用本机的 Excel 或 WPS 表格另存为 `.xlsx`，没有时用 LibreOffice，再按 xlsx 提取。打开副本前禁用宏、不更新外部链接；用户的原文件不被打开，也不改动。都转不成功时报告状态为 `failed`，请用户在 Excel 或 WPS 里另存为 `.xlsx`（或打印成 PDF），用第三节换上新文件，再提取一次。
- DWG、DXF 图纸读图上的文字：单行和多行文字、图框和图块里的属性（图号、图名多在这里）、引线文字，以及标注和表格里的文字。按"模型空间 / 布局 / 块"分段，标注合成"标注文字"一段。没用上的图库块和属性模板不读。DXF 要 Python 包 ezdxf；DWG 还要本机装 ODA File Converter，脚本把 DWG 复制到临时目录，转成 DXF 读完就删，用户的文件不动，全程在本机。读得出足够文字的记 `ok`；ezdxf 或 ODA 没装、转换失败的，声明过的图纸记 `drawing`，原因一栏写明缺什么、怎么补，不硬停。勾选框、填充、线条这类图形信息不是文字，读不出来，阶段 3 仍按图号看图。ODA 装在非默认位置时，把程序路径设到环境变量 `QINGTIAN_ODA_CONVERTER`。
- 电子交易系统下发的招标文件专用格式（如 `.hfszb`、`.18zhzb`）读不了，报"暂不支持的文件类型"。登记同一份招标文件的 PDF 或 Word 版。
- 路径太长（Windows 默认上限 259 个字符）导致读写失败时，原因一栏写明是路径太长。把项目目录放到更短的位置，或给来源文件改个短名，用第三节重新登记后再提取。
- 退出码：0 表示全部通过；1 表示有来源没通过；2 表示命令本身出错（如项目没有 `sources`）。

## 三、开工后到的补遗、图纸、样本

```powershell
python -X utf8 "<skill目录>/scripts/project_status.py" <项目目录> --add-source <文件> [--kind tender|drawing|sample]
```

- 不写 `--kind` 时按招标文件登记。补遗、澄清、答疑都按 tender 登记。
- 文件复制进对应目录。只想登记原路径、不复制时加 `--no-copy`。
- 项目里已有同名但内容不同的文件时，脚本拒绝，不覆盖。请用户改名后再登记，例如 `补遗2-工期.pdf`。
- 已登记的文件不能改登成别的类别。
- 新登记一个来源时，已完成的阶段 1、2 自动重开：已确认的规则卡随提取文本指纹失效，阶段 2 要按补遗重新核对（见 `stage-2-analysis.md` 第六节）。阶段 3 已完成的也一并重开，事实卡随提取文本和规则卡失效（见 `stage-3-facts-resources.md` 第六节）。登记后回到第二节重新提取。

## 四、看提取报告

逐行看 `analysis/extraction-report.md`：

| 状态 | 含义 | 怎么办 |
|---|---|---|
| `ok` | 文字足够 | 抽查一两页文本，确认不是乱码、页码顺序没乱 |
| `drawing` | 用户声明的图纸，提取不到足够文字，或本机读不了（如 DWG 缺 ODA File Converter） | 阶段 3 按图号人工读，事实出处写图号。原因一栏写了缺什么工具的，先告诉用户怎么装，装好后重新提取；用户不装的，请用户导出可复制文字的 PDF，用第三节按图纸登记 |
| `needs_ocr` | 文字太少，像扫描件 | 硬停。请用户提供可复制文字的电子版；用户同意时，由用户在本机用 OCR 软件转好文字版再登记。不得猜测内容 |
| `failed` | 打不开、格式不支持或路径太长 | 硬停。按原因处理（另存为 xlsx、换未加密的文件、缩短路径等） |

文字够数但内容明显是乱码（字体映射丢失），脚本判不出，也按 `needs_ocr` 处理，告诉用户原因。

## 五、完成阶段 1

```powershell
python -X utf8 "<skill目录>/scripts/project_status.py" <项目目录> --complete 1
```

以下全部满足才能完成，否则脚本逐条列出：

- 每个登记来源都在提取报告里，且提取时登记的类别与现在一致；
- 每个来源的状态是 `ok`，或者是用户声明的图纸、状态为 `drawing`；
- 来源文件在提取后没被替换或删除（按 sha256 核对）。

运行 `project_status.py <项目目录>` 可以随时看各阶段状态、登记来源数和规则卡状态（阶段 3 起还有事实卡、资源卡状态和登记的公司资源数，阶段 4 起还有响应矩阵状态和逐项撰写进度）。

## 六、本阶段的硬停止

- 招标文件、补遗、清单或样本提取不出文字（`needs_ocr`），或打不开（`failed`）（R9、R27）。
- 文本是乱码，或页码顺序明显错乱。
- 用户没有声明为图纸的文件，需要当作图纸处理：先问用户，由用户声明。
- 用户要求把招标文件正文、补遗或清单登记为图纸：说明这会绕过 R9，不照做。
