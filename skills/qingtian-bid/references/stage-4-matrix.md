# 阶段 4 响应矩阵细则

图文施组同时读 `visual-layout.md`，在 `analysis/visual-plan.md` 记录各评审项的标题条与正文框，以及图表与评审项、事实、工序、正文位置和页数预算的对应关系。该计划独立于矩阵 schema；图片占页包含在本项预算内，不能只算文字。

阶段 3 完成后读。目标是一份经用户确认的大纲（R12）。

大纲就是响应矩阵加篇幅预算，每项评审内容一行，写明：

- 本项必须写到的要点；
- 引用本项目的哪些事实、公司的哪些资源；
- ★条款和实质性要求落在哪一项；
- 预算多少页。

阶段 5 逐项撰写只按确认过的矩阵写。

命令里的 `<skill目录>` 是本 Skill 所在的目录（SKILL.md 所在目录）。路径可能带空格，引号要留。命令在哪个目录运行都可以。所有材料只在本机处理，不外传（R26）。

矩阵以 `analysis/response-matrix.json` 为准（决策 1A）。`response-matrix.md` 是脚本生成的视图，给用户看，不手改。

## 二、矩阵骨架

`scaffold_matrix.py` 要求阶段 3 已完成，按规则卡出骨架：

- **一项评审内容一行**：序号、标题照抄规则卡评审内容原文，顺序不变（R3、R4、Q1）。要点、事实留空，等你写。
- **预填控制点**：规则卡工程类别选的类别知识卡里，与本项标题对应方面的必备要点原文（决策 5-4A）。卡片是通用施工知识【推断】：本项目不涉及的删掉（写作时 W9 不再提示），要结合本项目的补上。标题含"重点""难点"的一项不预填，重点难点以招标文件点名的为准。选到但还没交付的卡先跳过。事实卡的现场限制禁止设的设施（材料堆场、加工区、办公区、生活区、室外堆放点，见 `scripts/site_limits.py`），卡片要点照常要求标注的，骨架改写成"现场不设……（现场限制 Fnn），写明场外解决方式；卡片原文：……"，原文留着备查，W9 仍按原文的叫法比对（第 6b 步，决策 S6-A）。骨架输出的 `site_limits` 列出认到的设施和出自哪条事实，认错或漏认的回阶段 3 改事实卡。
- **预填资源**：标题含"物资""机械""设备""劳动力"的项，填上资源卡对应一节的全部编号。
- **预填★落点**：去处为施组的强制条款，原文含"工期""质量""安全"的，落在标题含同一个词的那一项。招标指定的内容（重点难点、危大清单）不按这三个词猜，落在标题含"重点"或"难点"的第一项；评审内容里没有这一项的不预填，和用户商定落在哪一项（如主要施工方法、安全措施）。去处为提交前清单的不预填。
- **预填实施、进度、组织**（R13）：实施落在含"施工方法"的项，进度落在含"工期"的项，组织落在含"劳动力""质量""安全"的项。依据 `note` 留空，由你写。
- **页数预算**：
  - 规则卡有篇幅上限的，扣除封面目录（默认 2 页）和余量（默认 3 页）后，按示范文本默认页数的比例分给各项，以 0.5 页为单位，每项至少 0.5 页。凑整剩下的零头补给按比例最吃亏的几项，不全堆在一项上（Q5）。不是那 10 项的标题（如招标文件加的第 11 项"重点、难点"）按 3 页计权，其余各项仍按默认比例；全部不是那 10 项时等于平均分。
  - 没有篇幅上限的，按示范文本默认页数给，不是那 10 项的每项 3 页。
  - 上限扣除后不够每项 0.5 页时，脚本拒绝，先和用户商定篇幅。

预填都是按关键词猜的，必须逐项核对。项目里已有矩阵时，脚本不覆盖，骨架另存为 `analysis/response-matrix-候选-<时间>.json`，由你对照后手工并入。

规则卡评审内容为"招标文件未规定"（只有 T-合格 允许）时，脚本硬停，不编章节，按第五节处理。

## 三、填写矩阵

每项写成：

```json
{"no": 2, "title": "主要施工方法", "points": ["基础、主体、装饰各阶段的施工顺序和流水段划分", "高大模板和深基坑的专项措施"],
 "facts": ["F02", "F05", "F06"], "facts_note": "", "resources": ["E01"], "mandatory": [],
 "control_points": [], "pages": 13}
```

| 键 | 写什么 |
|---|---|
| `no`、`title` | 序号和评审内容原文，与规则卡一致，不改字 |
| `points` | 本项必须写到的要点，至少一条。对照规则卡里该项的档次原文写，让第一段能直接回答评审内容（Q2） |
| `facts` | 引用的事实卡编号。每项至少 2 条（W1）；确实用不到 2 条的，在 `facts_note` 写明原因 |
| `resources` | 引用的资源卡编号（P、E、L、S）。只能引用资源卡里有的（R7） |
| `mandatory` | 落在本项的强制条款编号（M）。去处为施组的每一条都要有落点（R5）；去处为提交前清单的不能写在这里，它们在阶段 8 逐条核对（决策 4c-4A） |
| `control_points` | 本项的控制点，自由文字，可以留空。骨架按类别知识卡预填，按本项目删改；大纲视图第五节列出每项的卡片必备要点和参考，删掉的要点写作时不再提示，留下的（原文还在，或改写后还带它的某个叫法）正文没写到才 W9 提示（决策 3c-1A、5-4A，第 6b 步改） |
| `pages` | 预算页数，正数，以 0.5 页为单位 |
| `cites` | 本项依赖规则卡的哪几行（决策 D9-1A），行键的写法见 `stage-3-facts-resources.md` 第三节。骨架预填评审内容这一行（`review_items.2`）和落在本项的强制条款；本项还用到别的规则（如工期 `schedule`）的，要补上。本项的评审内容和 `mandatory` 里的条款不写也算依赖，事实和资源走 `facts`、`resources`，不写在这里。没写算依赖全部规则行，规则卡任何一行变了都要重新确认 |
| `source` | 只在第五节的情形写：章节清单的出处 |

其他键一律不收。顶层另有三项：

- `front_pages`：封面和目录的页数，默认 2，计入上限。示范文本没写封面目录是否计入；2026-10-30 核对的一份合肥招标文件写明篇幅"包含封面和目录等所有内容"【一手】，招标文件没写的同样按计入估算【推断】。招标文件写明封面目录不计页数的，改为 0。
- `reserve_pages`：余量，默认 3 页，留给渲染误差和图表【推断】。
- `coverage`：实施、进度、组织三方面各落在哪几项（`items` 写矩阵序号）。分布在多项的，`note` 写明"已分布覆盖"及依据（R13、B11）。例如：

```json
"组织": {"items": [5, 6, 7], "note": "评审内容未单列项目管理机构，组织分布在劳动力、质量、安全三项"}
```

**篇幅**：封面目录、各项合计和余量加起来不得超过规则卡的篇幅上限。上限写的是"建议"，也照做（D7）。超了先压各项页数和余量。压缩会删掉评审内容要求的要点时，硬停，请用户取舍。

视图按锁定格式估算"一页约多少字"【推断】，只用来分篇幅。真实页数以第 4 步渲染计页为准（B2）。

## 四、请用户确认

先运行 `--check response-matrix`，问题必须清零（退出码 0）。然后把 `response-matrix.md` 给用户逐节说明：

1. 逐项矩阵：每项的要点、引用的事实和资源、页数；
2. 强制条款落点：每条★和实质性要求落在哪一项；
3. 实施、进度、组织落在哪里，依据是什么；
4. 篇幅预算：合计多少页，离上限还有多少。

只有用户明确表示同意，才运行 `--confirm response-matrix`。用户没回、只说"再看看"或提了修改意见，都不算同意。

以下情况确认会被拒绝：

- 阶段 3 未完成；
- 规则卡、事实卡、资源卡未确认或已失效；
- 校验还有问题。

确认时锁定矩阵自身和每行依赖的内容：评审内容这一行、`mandatory` 的条款、`cites` 的规则行、`facts`、`resources`（决策 D9）。确认后自身或依赖变了，大纲失效，`project_status.py <项目目录>` 显示原因和涉及哪几行（序号），阶段 4 不能完成，阶段 5 不能继续：

| 改了什么 | 怎么办 |
|---|---|
| 矩阵 | `--check`，请用户看改动的地方，同意后重新确认 |
| 规则卡、事实卡或资源卡 | 先按 `stage-2-analysis.md`、`stage-3-facts-resources.md` 重新确认那张卡，再核对矩阵受影响的行，重新确认大纲；没有行受影响的，重新确认那张卡就够了 |

**资源卡有缺口**（确认记录为 `outline_only`）：大纲照样可以确认，视图顶部会提示。但补齐资料、重新确认资源卡和大纲之前，阶段 5 不能开始（R8）。这时交给用户的就是大纲和缺口清单。

## 五、招标文件未规定评审内容（T-合格）

只有 T-合格 轨道的规则卡允许评审内容写"招标文件未规定"。这时没有原文可以照抄，章节不由你编：

1. 请用户给出章节清单和出处，例如"招标文件第八章施工组织设计格式列的 8 项"，或用户自己定的章节及确认日期。
2. 复制 `<skill目录>/templates/response-matrix.json` 为 `analysis/response-matrix.json`，按用户给的顺序逐项写 `no` 和 `title`。每项的 `source` 写出处，如"用户 2026-10-28 提供，依据招标文件第八章"。
3. 其余各键照第三节填写，资源、★落点和页数都没有预填，逐项手写。
4. 之后照第四节校验、确认。

## 六、完成阶段 4

```powershell
python -X utf8 "<skill目录>/scripts/project_status.py" <项目目录> --complete 4
```

以下全部满足才能完成，否则脚本逐条列出：

- 阶段 3 的完成条件仍然成立；
- 大纲已确认，且确认后锁定的内容都没变；
- 矩阵按当前校验规则复核仍然通过。

完成后读 `stage-5-writing.md`，开始逐项撰写。

## 七、本阶段的硬停止

- 评审内容招标文件未规定，用户也没给出章节清单：不编章节，不开始写矩阵。
- 篇幅上限装不下评审内容要求的要点：请用户取舍，不擅自删要点，也不擅自突破上限。
- 某条★条款或实质性要求找不到能落的项，或落了也写不出满足它的做法：问用户，不空挂。
- 用户要求把两项合并写、拆成更多项，或改评审内容的原文标题：说明 Q1 和 B1，不照做。
- 用户没有明确确认大纲。不得替用户确认，也不得在大纲确认前写中间稿（R12）。
