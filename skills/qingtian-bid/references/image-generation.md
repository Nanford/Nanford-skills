# 图片能力发现、生成与来源管理

阶段 4 策划插图时读；阶段 5 真正需要工艺场景图时执行。图文组织见 `visual-layout.md`。

## 先发现当前能力

图片生成取决于当前 Agent 会话，Python 环境自检无法知道工具是否已提供。

1. 查看当前会话声明的技能、工具与插件清单，按“生成/编辑栅格图片”的实际能力匹配；读取所选入口的说明。若有工具发现接口，按名称和说明检索。不能只因磁盘上存在技能文件就认定工具可用。
2. 用户已指定图片技能或插件时，优先采用；否则优先当前环境自带且确实可调用的图片生成工具，再考虑已连接插件。Codex 会话提供 `image_gen` 时使用内置生成路径，无须 API key；不写死本机路径，不要求其他 Agent 安装同一名称的工具。
3. 把实际发现结果记到 `analysis/image-capabilities.json`：`checked_at`、`agent`、`available_tools`、`selected_tool`、`mode`、`limitations`。未知与不可用分开记录；只记工具名称与能力，不读取或保存密钥。执行失败应如实登记，不把列出工具当作已生成。
4. 未发现可用生成工具时，继续文字、数据表和确定性技术图，并列明未完成的必需工艺配图作业。必需图片齐全后才交付整份成品。未经用户明确选择，不切换付费 API、安装插件、申请密钥或把真实资料上传到外部服务。

## 按图片用途选择制作方式

| 类型 | 制作方式 | 边界 |
|---|---|---|
| 工艺、保护、文明施工场景 | 发现的图片生成工具；每幅独立生成与检查 | 标记为示意；不充当项目实拍、企业业绩或已完成的作业记录 |
| 现场实景、现状管线、航拍底图 | 用户提供且可用的真实材料 | 保留来源，不凭空生成真实地形、楼栋或埋地设施；不擅自外传 |
| 横道图、网络图、组织关系图 | 从确认数据确定性绘制 | 日期、持续时间、依赖、关键线路须可复核；不用生成模型猜数字和连线 |
| 总平面、支护、节点详图 | 有依据的图纸与专业绘图方式 | 必要尺寸、比例与专业复核；AI 场景图不替代施工图或专项设计 |

不把检测当前 Agent 的工作委托给 `check_env.py`，该脚本仍只检查本地依赖。能力记录是当前会话的事实，不随分享包带入别人的环境。

## 每幅工艺图的执行顺序

1. 从已确认正文提炼对象、动作、约束和图题，关联事实/资源编号；先解决图文矛盾再生成。
2. 默认只发送去身份化的工艺描述；不上传招标文件、图纸、公司资料或完整正文（R26）。确需外部编辑真实材料时，先核实该材料的授权和用户是否允许外传。
3. 按工具文档调用。内置路径失败不能悄悄换为 CLI/API；批量需求也须逐幅保存结果并检查，不以一张拼贴图替代可独立排版的素材。
4. 提示词写明用途、工序、环境、构图、必须出现与不得出现的内容。生成底图通常不包含汉字、尺寸、公司标识或表格；中文图题和技术参数由文档或确定性绘图添加。不得在图中加入评审指令。
5. 查看实际生成图片，检查动作与装备、构造关系、安全防护、文字、身份及现场条件是否一致；问题只针对性修改。生成成功的提示不是检查结论。
6. 将选定原图保存到项目 `output/实施方案/images/`，避免引用会话临时链接或只留在 Agent 默认目录；修改另存版本，不覆盖已确认图片。记录原工具返回路径或资源 ID（不记临时令牌）。
7. 在 `analysis/visual-assets.json` 记录图号、图题、正文落点、用途、依据、生成工具、模式、最终提示词、图片哈希与检查结果。没有看过图片，不得把 `review` 项设为 true。项目事实/工法变化时同样重新人工核对，即使文件字节没有变化。
8. 执行 `python -X utf8 "<skill目录>/scripts/visual_assets.py" <项目目录>/analysis/visual-assets.json`，再进入文档组装。脚本核对记录完整性与文件版本，不能判断工程事实真伪或自动识别违章作业。

## 图片清单字段

顶层 `schema_version: 1`，`required_jobs` 与 `assets` 均为列表。空骨架见 `templates/visual-assets.json`。策划时先登记必要作业，例如 `{"id":"fig-02-01","kind":"ai-illustration","section":"2.1.1 作业面隔离"}`。`section` 使用图片前最近的 Markdown 标题全文，含编号。生成并检查后加入同一 `id`、`kind` 和 `section` 的素材记录。组装会拒绝未完成的必需作业、类型不符、放错小节、图题不符和素材版本变化。`assets` 每项：

```json
{
  "id": "fig-02-01",
  "file": "../output/实施方案/images/02-01.png",
  "kind": "ai-illustration",
  "caption": "图 2-1 作业面隔离示意（AI 生成）",
  "section": "2.1.1 作业面隔离",
  "purpose": "说明连续隔离与独立通行空间的关系",
  "source_refs": ["F-001", "R-001"],
  "generation": {
    "tool": "当前会话实际调用的工具名",
    "mode": "实际调用模式",
    "prompt": "实际使用的完整最终提示词"
  },
  "review": {
    "sha256": "查看并认可的文件实际哈希",
    "content": false,
    "safety": false,
    "identity": false,
    "legibility": false,
    "note": "查看结果与必要的专业复核结论"
  }
}
```

示例字段不是已检查结果，须替换真实值。`kind` 只收 `ai-illustration`、`source-photo`、`technical-diagram`；后两类不要求 `generation`，仍要求来源和四项检查。`source_refs` 由 Agent 回查事实卡、资源卡或图纸定位，脚本仅检查非空。AI 工艺图题必须包含“示意”。清单中的图片都须进入本次文稿；未采用的备选图留在工作目录，不加入交付清单。

生成记录与提示词保存在项目中供追溯，不作为施组正文或提交附件自动外发。
