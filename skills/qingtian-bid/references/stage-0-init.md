# 阶段 0 初始化细则

开工时读。目标是三件事：项目目录和状态文件建好，开工四问登记齐，成品格式经用户看过样张后明确确认并锁定。格式没确认，阶段 0 就没完成，不进入阶段 1。

命令里的 `<skill目录>` 是本 Skill 所在的目录（SKILL.md 所在目录）。路径可能带空格，引号要留。命令在哪个目录运行都可以。所有材料只在本机处理，不外传（R26）。

## 零、安装和环境自检

本 Skill 是一个完整的目录，整体复制到 Agent 的 skills 目录就能用，不依赖别的 Skill。路径可以带中文和空格。

开工前先跑一次自检。它只读，不改文件，不碰项目资料：

```powershell
python -X utf8 "<skill目录>/scripts/check_env.py"
```

- **退出码 0**：必需项（Python 3.10 或更新版本、`requirements.txt` 里的包）都满足，可以开工。
- **退出码 1**：缺必需项，补齐前不开工。输出里有补救命令，它装到当前这个 Python 上。装包会改动用户的 Python 环境，先告诉用户要装什么，用户同意后再装，装完再跑一次。
- **标为"提示"的项**不挡开工，把影响转告用户。最要紧的是 Word 或 WPS：没有它们，成品的目录和页码更新不了，阶段 7 的 B3 过不了，用户要把成品拿到装了它们的电脑上更新后保存。招标文件带 DWG 图纸的，第二要紧的是 ezdxf 和 ODA File Converter：没有它们，图上的文字读不出来，事实要按图号人工看图。ODA File Converter 是免费软件，许可不允许随 Skill 分发，请用户从 ODA 官网自己下载安装。其余影响和退路见自检的输出。

连 `python` 都运行不了时，请用户先装 Python 3.10 或更新版本。

自检只查注册表，不启动 Word 和 WPS，"通过"只说明装了，能不能真的导出，看开工出样张的结果。

## 一、开工四问

按 SKILL.md《开工四问》一次问完，用户已经说过的不再问。

1. 招标文件、补遗、图纸、工程量清单放在哪里。没有招标文件，硬停（R27）。
2. 有没有响应样本（R25）。样本只参考结构、详略和版式，不抄它的事实和承诺数字。
3. 公司资源资料：管理岗位与持证类别、机械设备、劳动力、主要物资（R7、R8）。建项目时会生成 `公司资料/`，下分 `项目管理人员/`、`机械设备/`、`劳动力/`、`物资/`，每个目录有一份说明，写明放什么、取什么、不取什么。开工时把这个目录指给用户，请用户把这次投标的资料放进去，子目录名不改。资料已经整理在别处的，用 `--resources` 登记那个路径，开工后到的用 `project_status.py --add-resource` 补登，都原地登记。脚本不复制公司资料。阶段 3 建资源卡前要放齐；到时仍缺的，资源卡写明缺口，施组只出大纲（R8，见 `stage-3-facts-resources.md`）。没放资料时，`project_status.py` 的概览从开工起每次都提醒。
4. 成品格式，见下一节。

交付范围为施工组织设计、完整 PDF 和提交前清单。项目名称从招标文件封面核实。

## 二、成品格式的四种定法

先用 `render_format_sample.py --list-presets` 把 F1～F5 的对照表给用户看。字段名可写英文键或中文名（如 `正文字号`、`body_size_pt`），字号可写磅值或中文字号名（`三号`、`小四`）。

| 用户的说法 | 怎么落到命令上 |
|---|---|
| 直接选一套预设 | `--format-preset F2` |
| 先选预设，再改个别字段 | `--format-preset F2 --format-set 正文字号=小四 --format-set 西文和数字字体="Times New Roman"` |
| 按维度逐项组合 | 先 `render_format_sample.py --list-presets --filter 正文字体=仿宋 --filter 行距方式=固定值` 找最接近的预设，再用 `--format-set` 改其余字段 |
| 完全自定义 | 以 F1 为底，用 `--format-set` 逐项给出用户说的每个字段；用户没说的字段沿用 F1，在确认卡上照实列出 |
| 不回答 | 框式新项目以 F1 字号和行距为底，采用主样张上边距 2.5 厘米、其余 2 厘米、连续排版且不单列目录，经样张确认 |

两条已定的默认（决策 2A）：

- 开暗标（`暗标模式=是`）时，页脚页码自动关闭，不用另设。暗标不设页眉页脚，也不接受页眉文字。
- F2 默认标题不分页、不生成目录、保留页码；招标文件另有规定时，阶段 2 按招标文件覆盖。

格式值不成立时（如固定值行距小于字号、字号名写错），脚本直接报错，不建任何目录。按报错改了再运行。

## 三、建项目

```powershell
python -X utf8 "<skill目录>/scripts/prepare_project.py" --root <工作区根目录> --project-name "<封面上的项目名称>" `
  --tender <招标文件> [--tender <补遗>] [--drawing <图纸>] [--sample <响应样本>] [--resources <公司资源资料>] `
  [--format-preset F2] [--format-set 字段=值] [--plain-sample]
```

`--root` 是放项目的工作区，项目建在它下面的 `bid-projects/` 里。用户指定了就用用户的；没说就用当前工作目录，不要建在 `<skill目录>` 里。

`--drawing` 只用于用户逐个说明是图纸的文件（决策 2A）。招标文件正文、补遗、工程量清单一律用 `--tender`，即使里面带图。

本机没有 Word 或 WPS 时加 `--no-pdf`，样张只出 DOCX。只想登记路径、不复制招标文件和样本时加 `--no-copy-sources`。

样张默认展示章内标题条、正文分块线框、表格与图题。用户选用无框或招标文件规定无框时，建项目或重新出样追加 `--plain-sample`；该选项只控制样张边框，字号、行距等仍按格式字段锁定。把采用的框式或无框版面登记到项目图文计划，后续重出样张沿用，遇到补遗按最新规定重审。

产出（项目目录为 `bid-projects/<项目名称>-<日期>/`）：

| 路径 | 内容 |
|---|---|
| `source/`、`source/drawings/`、`source/response-samples/` | 复制来的招标文件、图纸和响应样本 |
| `analysis/project-intake.md` | 开工四问的登记、范围、留到阶段 2 判定的事项、处理边界 |
| `analysis/format/格式样张.docx`（和 `.pdf`） | 按所选格式排的一页样张 |
| `analysis/format/格式样张-确认卡.md` | 每个字段的取值和出处、需另装的字体（W8）、确认命令 |
| `project-state.json` | 来源登记 `sources`（路径和类别，阶段 1 按它提取）；阶段 0 为进行中；所选格式登记为待确认（`format_review`，kind 为 kickoff），还不是 `document_format` |
| `公司资料/`（含 `项目管理人员/`、`机械设备/`、`劳动力/`、`物资/`） | 公司资料目录，每个目录一份说明；已登记为公司资源（`resources` 里记相对路径 `公司资料`），用户放进来的资料阶段 3 编目 |
| `analysis/extracted-text/`、`output/实施方案/`、`review/` | 后续阶段用的空目录 |

## 四、请用户看样张

把样张 PDF（没有 PDF 就给 DOCX）和确认卡发给用户，请用户看标题条、正文线框、图表位置、字体、字号、行距、页边距和页码。确认卡上"需另装的字体"不是"无"时，提醒用户评审端没装会替换字体，版式和页数随之变化（W8）。

只有用户明确表示同意（如"可以""确认""就按这个"）才算确认。用户没回、只说"再看看"或提了修改意见，都不算。

用户要改：

```powershell
python -X utf8 "<skill目录>/scripts/render_format_sample.py" --project <项目目录> --set 正文字号=小四
python -X utf8 "<skill目录>/scripts/render_format_sample.py" --project <项目目录> --preset F3
```

`--set` 在当前所选上改字段；`--preset` 换基础预设，之前改过的字段不再保留。每次都会重出样张，新的待确认记录替换旧的，然后再请用户看。

## 五、确认并锁定

用户明确同意后才运行：

```powershell
python -X utf8 "<skill目录>/scripts/render_format_sample.py" --project <项目目录> --confirm
```

确认后，格式写入 `project-state.json` 的 `document_format` 并锁定，用户自己的选择另存为 `format_selection`（阶段 2 招标文件覆盖以它为底），确认记录追加到 `format_history`，阶段 0 记为完成。接着进入阶段 1，见 `stage-1-extract.md`。阶段 0 只能这样完成，`project_status.py` 不接受手动开始、完成或重开阶段 0。

以下情况确认会被拒绝，按提示重新出样，再请用户看一次：

- 样张在出样后被改动或删除；
- 格式预设库在出样后有变化；
- 没有待确认的格式变更。

## 六、格式锁

- 项目格式未确认，或有变更待确认时，生成器和校验器在项目里都拒绝工作。
- 不得手改 `project-state.json`，也不得用 `--preset`、`--set` 绕过项目格式出稿或校验。项目里只认确认过的 `document_format`。
- 样张是唯一能按未确认格式排版的产物，由 `render_format_sample.py` 内部生成，命令行不开放这条路。

## 七、确认后改格式

用户确认后改主意，仍用第四节的 `--project --set` 或 `--project --preset`，变更类型记为 selection，同样要出样张、用户明确同意、再 `--confirm`。阶段 2 之后，招标文件规定了的字段不能再用 `--set` 改（脚本报错）；招标文件写的是"建议"、用户要保留自己的取值时，按 `stage-6-assembly.md` 第二节走偏离。

## 八、本阶段的硬停止

- 没有招标文件，或招标文件打不开（R27）。
- 封面上的项目名称与用户说的不一致。
- 用户没有明确确认样张。不得替用户确认，也不得在格式待确认时开始阶段 1。
