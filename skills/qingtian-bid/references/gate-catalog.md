# 门禁目录（阻断项 B、警告项 W）

> 使用阶段：阶段 5 写作自查、阶段 7 门禁。红线 R 见 `references/redlines.md`，青天逻辑 Q 见 `references/hefei-rules.md` 第十节。
> 门禁只做检查，不出分数。阻断项必须清零才能交付；警告项逐条处理，或书面说明不改的理由。阶段 7 的运行、理由记录和门禁报告见 `references/stage-7-gates.md`。

## 一、阻断项

| 编号 | 检查内容 | 来源 | 判定方式 |
|---|---|---|---|
| B1 | 评审内容全覆盖，一级标题与评审内容原文一致，顺序一致 | R3、R4、Q1 | 脚本比对规则卡与中间稿标题；阶段 7 另比对成品的一级标题（在 Word 里改过、删过、挪过的） |
| B2 | 渲染页数不超过篇幅上限。用 Word 或 WPS 计页，导出 PDF 兜底；仍无法计页时须人工确认 | R23、Q8 | 脚本在副本上计页，Word 和 WPS 都在时按较大页数判；失败转 PDF，再转人工给出页数 |
| B3 | 格式与最终格式逐项一致：字体、字号、行距、页边距、纸张。最终格式等于开工所选格式再被招标文件覆盖。只含图片的段落按单倍行距检查（固定值行距会把嵌入图裁成窄条）。暗标轨道下页眉、页脚、页码必须为空 | R11、Q8、Q12 | 阶段 7 在当前成品上跑 `--final` 格式校验，阻断项逐条进门禁 |
| B4 | 数值一致：工期、节点、人数、台数在各项之间一致，并与投标函、招标文件一致 | R15、R22 | 脚本抽取数字比对，人工复核 |
| B5 | 身份泄露：公司名、简称、商标、人名、证书号、电话、logo、文档属性。暗标轨道为阻断；其他轨道降为警告（所有轨道都默认身份中性写法） | Q12 | 脚本扫描（正文查中间稿；文档属性、封面目录、页眉页脚、图片名称、链接、文件名查成品），人工复核；文档属性不为空不能放行，清掉为止 |
| B6 | 文档清洁：隐藏文字、白色或极小字号文字、批注、修订、可疑嵌入对象、面向评审系统的指令性文字 | Q13 | 脚本扫描成品，不能说明理由放行 |
| B7 | 残留：非本项目的项目名、业主、地名 | Q10 | 脚本比对事实卡，人工复核 |
| B8 | 正文出现采购文件条款号、写作过程用语或 Markdown 泄漏 | R17、R18、R19 | 脚本扫描 |
| B9 | ★条款和实质性要求在施组中均有落点 | R5 | 脚本比对强制条款清单里去处为施组的条款：数值照原文，登记了关键词的逐个写到；招标指定的内容（招标文件点名要阐述的重点难点、危大清单）只按关键词核对。去处为提交前清单的在阶段 8 勾选（决策 4c-4A） |
| B10 | 施组引用的人员岗位、机械、劳动力、物资数据都能在公司资源卡里找到 | R7 | 脚本比对资源卡 |
| B11 | 实施、进度、组织已覆盖，或大纲已注明分布覆盖及依据 | R13 | 脚本比对响应矩阵 |
| B12 | 初步评审对照：规则卡初步评审表里与技术文件相关的每一条都有满足的证据，包括格式检查结果、工期与质量标准与原文一致、实质性要求有落点 | Q0、R5、R11 | 脚本汇总 B3、B4、B9 结果和人工核对项，用户逐行确认（锁定成品的 sha256 和初步评审表这一行；B3、B4、B9 有阻断时不能确认）；不能说明理由放行 |
| B13 | 施组出现有关投标报价的内容：报价用语（投标报价、综合单价、下浮率、费率等）和金额（数字或大写数字加"元"、人民币、￥），表格也查。部分招标文件在商务及技术文件初步评审的形式评审里列"未出现投标报价：商务及技术文件中未出现有关投标报价的内容"，不满足即形式评审不通过；没列这一行的，同样不写。所有轨道都阻断 | Q0 | 脚本扫描中间稿，人工复核：招标文件给的投资额、应急资金额度这类与报价无关的，用户说明理由后放行。成品里在 Word 另加的文字不查，改中间稿后重新出稿 |

## 二、警告项

| 编号 | 检查内容 | 来源 |
|---|---|---|
| W1 | 某项引用的项目事实少于 2 条 | Q3、Q4 |
| W2 | 某项没有可考核的量化指标 | R14、Q3 |
| W3 | 套话词密度过高 | Q6 |
| W4 | 疑似整段抄录规范原文或网络文本 | Q7、Q10 |
| W5 | 某项页数偏离预算超过 30%。成品计页能读到行位置时精确到行；只能按整页计时，差 1 页以内不报 | Q5 |
| W6 | 碎片清单、括号堆砌、正文表格化 | R16、R20 |
| W7 | 某项第一段没有直接回答该项评审内容 | Q2 |
| W8 | 用了非系统自带字体（如仿宋_GB2312、方正小标宋）。评审端没装就会替换字体，版式和页数随之变化。按成品各处文字实际生效的字体查 | Q8 |
| W9 | 规则卡工程类别选的类别知识卡（`references/category-cards/`）在本项的必备要点，确认过的矩阵这一项还留着（原文还在，或改写后还带它的某个叫法），正文一个叫法都没写到；阶段 4 按本项目删掉的不再提示。只是关键词比对，每项最多一条提示，合并列出没写到的要点；标题含"重点""难点"的一项不查（重点难点以招标文件点名的为准）。卡片是通用施工知识【推断】，本项目不涉及的说明理由即可，不为凑关键词硬写 | Q4 |
| W10 | 正文要设现场限制禁止的设施：确认过的事实卡里有禁止词（严禁、不允许、不具备等）在前、设施叫法在后的分句（如补疑写"现场不具备且不允许设置办公区、生活区""严禁在室外堆放"），正文某句写到这种设施（材料堆场、加工区、办公区、生活区、室外堆放点，叫法见 `scripts/site_limits.py`），同一句却没有不设、不在、场外、租用这类处理词。表格也查，每项每种设施一条提示。只是叫法比对【推断】：一句里既写不设甲又写设乙的会漏，确属误报的说明理由即可 | Q3、R15 |

## 三、编号规则

编号一经发布不重排。新增检查项接在末尾编号；某项不再适用时，在本表注明适用条件，不删除编号。
