# 阶段 6 出稿细则（含阶段 2 的招标文件格式覆盖）

本文件管成品格式从解标到出稿的全过程。第二节在阶段 2 解标时执行，第三至七节在阶段 6 执行，第六节的 `--final` 校验在阶段 7 门禁 B3 执行。阶段 6 的完成条件和阶段 7 的全部门禁见 `stage-7-gates.md`。

命令里的 `<skill目录>` 是本 Skill 所在的目录（SKILL.md 所在目录）。路径可能带空格，引号要留。命令在哪个目录运行都可以。所有材料只在本机处理，不外传（R26）。

## 一、前提

- 阶段 0 的格式已确认锁定（见 `stage-0-init.md`），阶段 2 的招标文件格式覆盖也已确认。项目里有待确认的格式变更时，生成器和校验器都拒绝工作。
- 阶段 5 各项评审内容的中间稿都已经用户确认。

## 二、招标文件覆盖格式（阶段 2 执行）

优先级按 D7：**招标文件（含补遗）> 开工所选 > F1**。招标文件的规定永远叠加在用户自己的选择（`format_selection`）上，不叠加在上一次覆盖的结果上。

### 1. 写招标文件格式规定

解标时把招标文件（含全部补遗、澄清）对成品格式的规定写进 `analysis/tender-format.json`：

```json
{
  "document": "招标文件第六章 投标文件格式",
  "requirements": [
    {"field": "正文字体", "value": "仿宋", "kind": "要求", "source": "第六章 3.1 第42页"},
    {"field": "正文字号", "value": "四号", "kind": "要求", "source": "第六章 3.1 第42页"},
    {"field": "一级标题字号", "value": "三号", "kind": "建议", "source": "第六章 3.2 第42页"},
    {"field": "暗标模式", "value": "是", "kind": "要求", "source": "暗标编制要求 第2条 第45页"}
  ],
  "penalty": {"text": "如不符合上述要求将酌情扣分", "source": "第三章 技术文件详细评审标准 注1④ 第61页"}
}
```

写法规则：

- `field` 只能是格式记录的字段，写英文键或中文名，全表见确认卡。字体颜色、装订、份数、图表要求等格式记录装不下的规定写进规则卡；篇幅上限交给门禁 B2。
- 一条规定拆成单个字段写。"正文四号仿宋"写成正文字体、正文字号两条。招标文件只说"标题"、不分级的，一至三级各写一条，出处相同。
- `kind` 按原文措辞判断："应""须""必须""不得"写"要求"；"建议""宜""可""推荐"写"建议"。判不清就硬停，问用户。
- `source` 写章节和页码，必填。
- 同一字段只能有一条。补遗改了某条，就改那一条并换成补遗的出处，不并列两条。
- 招标文件的分级说法与格式记录的字段对不上（如单独规定表格字号、只规定四级标题），硬停，问用户怎么落。
- `penalty` 可选：评审注释写了不符合编制建议就扣分的（2026-10-30 核对的两份合肥招标文件都写了"如不符合上述要求将酌情扣分"），原文照抄进 `text`，出处写进 `source`。规则卡脚手架的摘要会单列这句（"扣分原文"）。规则卡评审注释里有扣分句、这里又有"建议"的，漏写 `penalty` 时第 2 步拒绝运行，阶段 2 也不能完成。

招标文件对格式没有任何规定时，不写这个文件，不运行覆盖，在规则卡里写明"招标文件对格式无规定，沿用开工所选"。

### 2. 出差异和新样张

```powershell
python -X utf8 "<skill目录>/scripts/render_format_sample.py" --project <项目目录> --tender-format <项目目录>/analysis/tender-format.json
```

产出：

- `analysis/format/格式差异-招标文件.md`：每条规定一行，列为"字段 / 所选 / 招标文件要求 / 最终采用 / 结果 / 出处"。结果有四种："一致""按招标文件覆盖""偏离（用户同意）""随暗标关闭"。
- `analysis/format/格式样张-招标文件覆盖.docx`（和 `.pdf`）及确认卡。
- `project-state.json` 登记一条待确认变更，kind 为 tender。确认前不能出稿。

### 3. 请用户确认

把差异表和新样张一起给用户，逐行说明。三条默认：

- 招标文件写"建议"的，也默认照做。用户要保留自己的取值，须明确同意偏离，带上记录重出：
  `--tender-format <文件> --deviate 一级标题字号 --deviation-note "用户 2026-10-28 明确同意保留小四"`。偏离记录写进该字段的出处。
  - 招标文件写了扣分句的，同意偏离之前，先把差异表里的"扣分原文"一行原样给用户看，说明偏离可能被扣分。用户看过仍明确同意的，才记 `--deviation-note`；没给用户看过原文，不得记同意。脚本把扣分原文带进偏离字段的出处。
- 招标文件写"要求"的，不得偏离，脚本直接报错。用户坚持时，说明这会造成初步评审不通过的风险，请用户向招标人澄清，不替用户改。
- 招标文件要求暗标的，页脚页码自动关闭，差异表多出一行"随暗标关闭"（决策 2A）。招标文件同时要求暗标和页码，脚本报"合起来不成立"，硬停，请用户向招标人澄清。

招标文件的规定与所选格式合起来不成立时（例如招标文件只规定"固定值行距"，所选却是 1.5 倍行距），脚本报错并说明原因。按报错用 `--set` 调整招标文件没规定的字段；需要时可以把招标文件规定的字段按招标文件的取值一并写入，例如 `--set 行距方式=固定值 --set 行距值=28`。`--set` 写成与招标文件不同的值，脚本拦下。

用户明确同意后才运行 `render_format_sample.py --project <项目目录> --confirm`。确认后最终格式写入 `document_format`，招标文件规定写入 `tender_format`。用户自己的选择保持原样，不被招标文件改写。

### 4. 补遗

补遗改了格式规定时，把 `tender-format.json` 改成招标文件加全部补遗之后的完整现行规定（不是只写补遗那几条），再运行第 2 步。补遗删掉的规定，对应字段回到用户自己的选择。之前同意过的偏离不会自动带过去：仍要偏离的，重新带 `--deviate` 和 `--deviation-note`；忘了带，差异表会显示"按招标文件覆盖"，确认前核对。

## 三、出稿

按规则卡评审内容的顺序写组装清单 `output/manifest.json`。`files` 里的相对路径相对于清单所在目录。

每项评审内容一个文件，命名为 `实施方案/NN-<评审内容原文>.md`，其中 NN 是规则卡里的序号，一项不缺。封面和目录放在最前，用 00 开头：

```json
{"header": "XX 项目施工组织设计", "files": ["实施方案/00-封面.md", "实施方案/00-目录.md",
  "实施方案/01-工程概况.md", "实施方案/02-主要施工方法.md", "实施方案/03-拟投入的主要物资计划.md"]}
```

```powershell
python -X utf8 "<skill目录>/scripts/build_response_docx.py" --manifest <项目目录>/output/manifest.json --output <项目目录>/output/施工组织设计.docx
```

- 成品固定为 `output/施工组织设计.docx`，不放进 `output/实施方案/`：那个目录只放中间稿和 00 开头的封面、目录，成品旁的构建、校验、计页报告放进去会和中间稿混在一起。阶段 7 门禁只认这个路径。
- 格式取自项目锁定的 `document_format`，不另传格式。生成器同时在成品旁写同名的 `.build-report.json`，记录格式、来源文件及其出稿时的 sha256 和警告（如图片缺失）。阶段 6 凭它核对成品用的正是确认过的那版中间稿（`stage-7-gates.md` 第一节）。
- 成品不带作者、备注等文档属性，并打开 Word 的"保存时从文件属性中删除个人信息"（WPS 也认）：在 Word 或 WPS 里更新目录后保存，不会把电脑账户名写回作者。图片名称一律改成"图片N"，不带原文件名（文件名可能含公司名）。
- Markdown 的版式标记（封面、目录、分页）见 `build_response_docx.py` 头注释。格式要求生成目录（`require_toc`）的，在目录位置放 `<!-- toc -->`。
- 标题编号写在标题文字里（一、/（一）/ 1. / 1.1），不用 Word 自动编号。
- 标题的字体、字号、加粗只由标题样式决定。不要在 Word 里给标题文字单独设格式：Word 更新目录时会把标题文字上单独设的字体复制进目录条目，校验会报目录字体不符。

## 四、图片

图文响应文件按 `visual-layout.md` 策划与排版，生成工艺图前按 `image-generation.md` 发现当前 Agent 能力。组装清单写入 `"visual_manifest": "../analysis/visual-assets.json"`。项目清单登记了必需配图时，生成器也会自动读取该清单，核对每张必需图是否已生成并插在指定小节，且图题和文件哈希与检查记录一致。

支持 `panel-start/panel-end` 模块边框、`panel-grid-start/panel-end` 连续分隔线框、`gallery-start/gallery-end` 两至三图并排、`table-caption` 表题和 `table-widths` 列宽权重，完整语法见 `visual-layout.md`。图题自动生成为可检索的正文文字，保持项目正文字体、字号和行距。表格无填充、黑色细线、重复表头；长数据行允许跨页。不要为压缩页数缩小图题或正文。

组装前核对 `analysis/visual-plan.md` 与本次中间稿。采用框式样张的，标题条、正文框和相关图表须按计划落位；漏标、框线错位或图片组脱离正文时，修正中间稿并重出，不在成品里用截图拼版。招标文件规定无框时，以无框版面出稿。

构建报告同时保存实际嵌入图片的 sha256 及图片清单版本，图片或清单变更后阶段 6/7 要重新检查和出稿。普通独立图在旧调用方式下仍可生成；图文流程统一使用图片清单，不以旧方式绕过图片检查。

- 图单独占一行：`![施工总平面布置图](images/总平面.png)`，相对路径相对于 Markdown 文件所在目录。生成器把图居中、缩放到版心内。
- 只含图片的段落固定用单倍行距。固定值行距会把嵌入图裁成一行高的窄条，校验器对此判阻断。
- 不要把图嵌在文字段落中间。浮动图不做行距检查，但尽量不用。
- 图片文件缺失时，生成器放一段可见的占位说明并在构建报告里列出，`--final` 校验会拦下。

## 五、暗标

- 暗标模式不设页眉、页脚、页码。清单的 `header` 留空，命令行不加 `--header`。传了页眉文字，生成器直接报错。
- 校验器检查页眉页脚没有任何文字、域、图片或标志，正文没有页码域。
- 身份零泄露（Q12）不归格式校验管，由阶段 7 门禁检查。

## 六、校验

阶段 6 出稿后先自查版式：

```powershell
python -X utf8 "<skill目录>/scripts/validate_docx_format.py" <项目目录>/output/施工组织设计.docx
```

- 格式取自项目锁定的格式。逐段核对字体（中文槽和西文槽）、字号、加粗、斜体、颜色、行距、标题段前段后和顶格、正文首行缩进、页面和页边距、标题分页、目录和页码，以及图片段落的行距和暗标规则。
- 结果写入成品旁同名的 `.format-report.json` 和 `.format-report.md`。阻断项必须清零，警告逐条处理。
- 版式模式下，未更新的目录域只报警告。

交付前（阶段 7，门禁 B3）：

1. 在 Word 或 WPS 里打开成品，更新目录和页码（全选后 F9，或右键"更新域"），保存。
2. 保存后重新校验，加 `--final`：

```powershell
python -X utf8 "<skill目录>/scripts/validate_docx_format.py" <成品DOCX> --final
```

3. 扫成品、计页（门禁 B6、B5、W8，B2、W5）。阶段 7 用 `check_qingtian_final.py <项目目录>` 一次跑完第 2、3 步和其余门禁，并写门禁报告（`stage-7-gates.md`）；下面两条命令单独查看某一项时用：

```powershell
python -X utf8 "<skill目录>/scripts/scan_docx_hygiene.py" <成品DOCX>
python -X utf8 "<skill目录>/scripts/report_page_numbers.py" <成品DOCX>
```

文档属性里有作者、单位或自定义属性的（多半是在别的电脑或老版本 Word 里存过），运行 `scan_docx_hygiene.py <成品DOCX> --clean-properties` 清掉。它先备份成 `<成品>.clean-<时间>.bak`，只改文档属性，成品在 Word 或 WPS 里开着时拒绝运行。清理会改变成品的 sha256，之后从第 2 步重新校验。顺序固定为：Word 保存 → 清属性 → `--final` → 门禁。

计页在临时副本上做，成品不更新、不保存。本机 Word 和 WPS 都在时两边都计，按较大的页数判 B2。都计不出来时脚本先在副本上导出 PDF 计页；仍失败的，请用户在 Word 或 WPS 里更新目录后导出 PDF，运行 `--pdf <PDF>`，或看状态栏的总页数，运行 `--manual-pages <页数> --reason "<怎么数的>"`。这两种只在自动计页失败之后才收，结果都锁定成品的 sha256。

`--final` 下，待补材料、未更新的目录占位、页码占位都是阻断项。中文版 Word 另存时会把样式 ID 改成数字（Normal 变 1、heading 1 变 3），校验器按样式名识别，不受影响。凡是在 Word 里又改过、存过，都要重新校验，以最后一次报告为准。

校验只读 OOXML 属性，不看渲染效果。渲染页数由门禁 B2 另行计页（`report_page_numbers.py`）。图文成品还须按 `visual-layout.md` 逐页查看最终 PDF 渲染图片；没有可用渲染引擎时明确页面视觉检查未完成。

## 七、本阶段的硬停止

- 项目格式待确认，或 `document_format` 缺失：回到阶段 0 或本文件第二节，不绕过。
- 校验有阻断项：改稿或改格式后重出重验，不交付带阻断项的成品。
- 招标文件格式规定的"要求"与"建议"判不清，或分级说法对不上格式记录的字段。
- 招标文件同时要求暗标和页码，或其他规定之间互相冲突。
