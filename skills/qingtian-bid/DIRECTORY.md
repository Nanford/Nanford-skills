# qingtian-bid 目录说明

本目录是 `qingtian-bid` Skill 的源目录，遵循 SKILL.md + references/ + templates/ + scripts/ 的通用 Agent Skill 结构。它面向招标文件启用青天大模型 AI 类人评审的项目，不看地区和行业（见 SKILL.md《适用范围》），目前只做施工组织设计和提交前清单：第一层是投标基础红线，第二层叠加青天 AI 类人评审与暗标规则。商务文件由用户另行编制，本版本暂不生成。

## 已知限制（待修）

v1.0 第 6b 步真实招标文件冒烟发现、当时没修的问题（v1.0 时这一节叫"已知限制（V2）"，V2 指以后的版本）。v2.0 修哪几条还没定，已修的在条目里注明：

1. 多卡项目的控制点过多：选了五六张卡的项目，一项可能预填几十条，W9 一条提示里列十几个点；建筑类要点也会漏到市政项目（如道路项目出现"楼内垂直运输""吊顶内"）。可选办法：卡上要点标适用场景（室内、室外、在用建筑）按主卡过滤，或每项按页数设上限、超出的放备选。
2. ~~清单主要分项每张卡最多 8 条，真正的主要分项可能漏。~~ v2.0 第 2g 步已改：每卡保底 8 条、总数最多 150 条，没进候选的列在 `analysis/清单未进候选.md`。工程量大不等于造价高，总数超过 150 的大清单还是要人对着看。
3. 0301 机械设备安装不归任何卡：卡片的名称关键词对整张卡生效，没法只收泵、风机；0313、0116 是措施项目，不归卡（见 `references/category-cards/DIRECTORY.md`）。
4. `--check fact-card` 不强制写结构形式；招标文件本来没写时，由 W9 提示。
5. 资源卡不核对机械、工种和工程类别是否匹配（道路项目没有摊铺机、压路机也能通过）。
6. 候选里有杂行：事实卡和评标办法候选夹着页脚、页码行；清单项目特征里的★没清掉；工程类别线索偏多。
7. W7 对"工程概况"只认"概况"两个字，第一段直接写项目本身也会提示，容易逼出"本项目工程概况如下"这种套话，需要时写不改理由。
8. W9 按字面比关键词：近义写法对不上（"地下、地上、墙上、空中的各类管线"对不上"地下管线"）；两张卡的同一句要点会在一条提示里重复；招标文件没定安全目标时，"安全目标与招标文件一致"照样预填。
9. W10 和矩阵骨架的改写只认 `scripts/site_limits.py` 表里的五种设施；"临时设施"太宽没收；一句里既写不设甲、又写设乙的会漏报。

## 依赖

- 脚本运行需要 Python 3.10 或更新版本、`python-docx>=1.1` 和 `pypdf>=4.0`（`pip install -r requirements.txt`）。Python 下限是从代码推出来的，实测只在 3.14 上跑过。
- Microsoft Word 或 WPS 文字可选，但成品要靠它们更新目录和页码，否则阶段 7 的 B3 过不了；它们还用于样张导出 PDF（没有时加 `--no-pdf`）和自动计页（没有时用 `--pdf` 或 `--manual-pages`）。
- 开工前用 `scripts/check_env.py` 查一遍，缺什么它会给出补救办法和影响。
- 规则来源是 `references/redlines.md` 的投标基础红线，以及合公业〔2026〕30 号导则和合肥技术评分合理价格法示范文本（引用页码，原件不入库）。
