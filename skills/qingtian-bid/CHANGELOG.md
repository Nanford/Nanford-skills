# qingtian-bid 更新日志

版本号写在 `SKILL.md` 头部的 `metadata.version`。值要加引号，否则 YAML 会把 `1.10` 读成 1.1。

分享包 `dist/qingtian-bid-v<版本号>.zip` 由仓库根目录的 `tools/build_package.py` 导出，只含已提交的文件；发给测试人员的测试版（版本号 `X.Y-beta.N`）另打测试包 `dist/qingtian-bid-v<版本号>-测试包.zip`（`--bundle`），带使用说明和安装说明。打包前要先改版本号、在本文件记下这一版，并提交。

每一版有一个本地 tag `qingtian-bid-v<版本号>`，指向打包用的提交。zip 不入库，需要时从 tag 重新导出。

## v2.0-dev（开发中，未发布）

v2.0-beta.2 之后的改动记在这里。

- **GitHub 单独分发**：通过 `Nanford/Nanford-skills` 单独安装本 Skill。由 GitHub CLI 记录安装来源，首次使用时检查并提醒，用户明确要求时更新当前副本。

- **主样张、配图作业和完整 PDF（2026-11-13）**：按已确认主样张落实居中章标题、标题条、连续正文框、跨页表格及同版心组图。新增必要配图作业的完整性、类型和小节检查。DOCX 放行后可本机导出同版 PDF，清理附带身份属性并绑定两份文件哈希，逐页检查后交付。

- **框式版面成为默认（2026-11-12）**：开工与格式覆盖样张默认展示黑色分块线框、表题和图题；无框项目用 `--plain-sample` 出样。将已确认的版面贯穿图文计划、逐项撰写、组装和页面验收。字体、行距等锁定规则不变，招标文件优先。

- **框式版面补齐（2026-11-12）**：新增 `panel-grid-start` 连续分隔线框，标题条、正文与组图按参考样式组成可编辑内容模块；边框紧接并对齐表格，保留既有标题与正文缩进。原 `panel-start` 兼容保留。版式细则要求实际检查内容框架、跨页续框和孤立图片组。

- **图文施组规范（2026-11-12）**：归纳四份本地参考文件的模块化图文组织，不带真实项目名、原件或图片入库。新增图文版式、图片能力发现与生成细则，区分 AI 工艺示意、现场照片和数据驱动技术图；评分依据仍取本项目招标文件，不臆造模型权重。生成器支持黑色无填充模块边框、两至三图并排、可检索图题、表题、列宽权重及重复表头。新增图片清单与检查哈希，构建报告追踪实际嵌入图片，阶段 6 和最终门禁发现图片/清单变化后要求重出。五套既有格式预设和正文标题层级保持兼容；版式仍须真实渲染检查。

- **提取失败的原因不再丢（修复）**：老式 `.doc`、`.xls` 先经 Word、Excel 或 WPS 转换，失败后转去 LibreOffice。以前 Office 那一路的报错被直接吞掉，两路都不成时提取报告只写"转不了"，分不清是没装、被占用还是文件打不开。现在把 Office 的报错附在失败原因后面（压成一行，只留开头 300 字）；`.doc` 用 LibreOffice 转换失败时也给出另存为 `.docx` 的办法，不再只抛命令行错误。转换成功的路径没有变化。
- **规则时效复查（2026-11-10）**：评定分离办法（合政秘〔2024〕78 号）按印发日和二年有效期已于 2026-11-08 满两年，暂行办法 2026-11-23 到期。这次联网复查，两份文件的续期、修订或替代文件都没查到，也没能打开官方原文，只查到二手转述。`references/hefei-rules.md` 的汇编日期、来源表、第三节、第十二节时效和第十三节照此改写：定性定量评审法的项目以招标文件为准，开工时告诉用户；`package/使用说明.md` 的已知限制同步。没有发现 2026 年 6 月以后新的青天规则或示范文本修订。
- **文档对齐（2026-11-10 自查）**：`SKILL.md` 的 description 加一句不触发的情形（没启用青天、也不是合肥施工项目的一般投标），开工处写明成品的计页和更新目录要靠 Windows 上的 Word 或 WPS、本机没有时开工就告诉用户；仓库 `README.md` 不再写"功能和 v1.0 相同"，列出 v2.0 加了什么；`DIRECTORY.md` 把 v1.0 的建设和安装记录标成历史，"已知限制（V2）"一节改名"已知限制（待修）"；Python 实测范围各处统一为 3.13 和 3.14。description 改了以后还没有实测触发，装上 v2 后要试一次。

## v2.0-beta.2（2026-11-09，测试版）

第二个发给测试人员的版本，在 v2.0-beta.1 上加了模拟自评。卡片 schema 没变，用 v2.0-beta.1 建的项目可以接着用这一版做。

- **已知限制**：v2.0-beta.1 的已知限制都还在。另加一条：模拟自评没有用公布的真实得分校准过，只在虚构项目上走过，模拟分可能整体偏高或偏低。

- **模拟自评（2026-11-09，用户定 1A、2A、3A、4A）**：阶段 7 完成后可选，对当前成品模拟青天的评审项解析、溯源解析、逻辑论述和评审建议四步，按招标文件的评分标准给每项评审内容模拟档次、模拟分和理由，脚本加总分，出 `review/自评/自评报告.md`。不是门禁，不挡任何阶段；报告标明"模拟，不是青天的评分"。
  - 评分标准 `review/自评/评分标准.json`：分值、区间法的档次或固定分值法的可取分值、覆盖哪几项、评分标准原文，分值和档次各带一份 `ref` 回原文查；示范文本结构（一个评审因素整体打分）和逐项给分值都能写。
  - 评分由新会话或子代理做，只看评审材料（评分标准原文和成品分节正文）和事实卡；脚本不收同一会话的评分。
  - 脚本核对：每项都评；分数落在所写档次或是可取分值；导则 2.2.2 要充足理由的分数写了理由；未提供的 0 分；出处逐字摘自本项章节；没给满分写失分点和怎么改；整体分在各项分之间；不预测入围、中标；评审人不能自己写总分。
  - 只评本 Skill 出的、过了阶段 7 的成品（2A、3A）。成品再存、评分标准改动或阶段 7 重开，分数作废。评外来标书、拿真实得分校准以后再做（3B）。
  - 类人评审预演仍然不出分数。
  - 新增 `scripts/self_score.py`、`references/self-score.md`、`tests/test_qingtian_self_score.py`；进度摘要多一行"模拟自评"。

### 硬停止的原文

SKILL.md《硬停止》逐条对应下面 13 行。旧名词换成了本 Skill 的说法：extraction-report 是提取报告，material-gate 的 outline_only 是资源卡有缺口，hard-parameters 和 format-clone-checklist 并入规则卡和招标文件格式规定，full 模式下的商务资料对应阶段 8 的商务侧条目。第 13 行拆成三条，政采、磋商、节能产品、答辩、建造师几条按需触发。

- 招标文件缺失或不可读；extraction-report 非 gate_ok（failed/needs_ocr）
- 扫描版PDF导致强制条款或官方格式表无法提取（须 OCR，见 stage-1）
- ★/强制/否决条款含义无法确定
- 资格条件缺少必需证据；material-gate 为 outline_only 却要写详细事实正文
- 承诺、价格、服务期、质保、人员、证书、业绩需要公司层面决策
- 招标文件要求的官方表格文本尚未提取到
- hard-parameters / format-clone-checklist 未完成或仍有缺口
- full 模式下商务资料未备齐且用户尚未说"继续"
- 大纲未获用户确认却准备写正文
- 上一章未获用户确认却准备写下一章
- 政采"专门面向中小企业"而我方为大中型企业 —— 无投标资格，立即告知用户，停止编制
- 磋商/谈判类的首次报价与最后报价底线未获用户书面授权
- 强制采购节能产品缺证书或已过期；评定分离项目答辩关键人档期未确认；工程类建造师/安全B证人选未定
