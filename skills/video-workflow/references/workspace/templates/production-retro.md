# 制作复盘提示词

用途：一段实质返工结束后，或整期交付后，复盘制作过程并提出规则修改建议。与平台数据复盘（AGENTS 第 15 节）分开进行。方法依据见 `docs/EDITING_METHOD.md` 第 4.8 节。

输出位置：`projects/<项目>/retro/production-retro.md`。只输出建议，不直接修改规则、技能或 `DESIGN.md`。

## 提示词

复制以下内容，把方括号里的范围换成实际项目：

```text
请基于本项目的真实文件做一次精简制作复盘。
范围：[projects/<项目> 全部 / 具体平台与镜头 ID]
输入：project.json、各平台 shots.json 与 timeline.json、qa/report.json、返工前后的文件差异（git diff 或版本文件），以及记录下来的主理人原话。不凭记忆补细节，文件里没有的写「未记录」。

1. 满意的画面：精确到镜头 ID 或静帧路径，写为什么好、可量化的特征（字号、停留时长、运动时长、画面占比等），作为今后的对标样例。本期没有就写「无」。
2. 真实发生过的返工，每条写：
   - 主理人原话（原样引用）；
   - 问题层级：事实 / 文案 / 配音 / 字幕 / 画面 / 节奏 / 音效与配乐 / 包装；
   - 返工轮次与最终解法；
   - 判断：规则没写，还是写了没执行。写了没执行的，只改触发入口（在哪一步、读哪份文件时应当看到），不新增条文；需要写入的规则保留正反两面，不能丢掉原话里的任何一半。
3. 可删减项：本期没用上或造成负担、可删除或合并的规则与检查；各镜头的返工轮次。
4. 候选想法：未经验证的想法单列，不写成经验。
5. 分类：把通用方法、系列视觉偏好和本期特例分开。先检查 AGENTS.md、docs/EDITING_METHOD.md、docs/DESIGN.md 和相关技能 SKILL.md 是否已有相同条目，能改原条目就不新增。
6. 修改建议：列出具体文件与简短改法。通用方法落 AGENTS.md 或 docs/EDITING_METHOD.md，系列视觉落 docs/DESIGN.md，环节工具的坑落对应技能 SKILL.md，本期特例只留在本复盘。公共规则只用中性描述，不写入本期的私人路径和素材。
7. 本次只交建议，不修改任何规则或技能文件。
```

## 完成标准

- 有正面样例，或明确写「本期无」。
- 每条经验都有真实问题、解法和适用边界。
- 有可删减项，或说明本期没有发现。
- 没有把单期的帧数、构图或个人偏好写成跨项目默认。

主理人选定建议后，再按范围修改对应文件，检查受影响的引用与任务入口，并按 AGENTS 第 16 节提交。
