# 成片验收与首轮试运行

## 1. 完成状态

| 状态 | 必须具备的证据 |
|---|---|
| 规范已交付 | 工作流、执行规范、数据合同、来源和输入模板存在且相互一致 |
| 最小链路已测试 | 实际生成并解码测试视频，保留输入、工程和检测结果 |
| render_complete | 当前版本正式 MP4 存在，自动检查通过，无已知技术阻断项 |
| delivery_ready | 正式交付文件齐全，事实、视听与授权检查通过 |
| ready_to_publish | delivery_ready，且具体账号和版本获发布授权，实际平台上传预览及声明检查通过 |

未测试项记为 `not_checked`。平台预览待检查不阻止本地成片交付，但不能标为 ready_to_publish。此文件列出验收要求，不能单凭文件存在声称测试通过。

## 2. 成片检查表

| 类别 | 检查与阈值 | 方法与处理 |
|---|---|---|
| 内容 | 一条主问题；开头的承诺在片中兑现 | 对照脚本与完整视频；不兑现则改开头或补证据 |
| 事实 | 关键数字、价格、功能、日期、排名和收益有依据 | 对照 claims、来源与实测；未知主张不得入片 |
| 演示 | 实际操作与口播一致，生成画面不冒充实测 | 检查相关源素材和镜头；参考视频摘要不能代替查看 |
| 权利 | 素材、声音、音乐、字体的来源与使用范围清楚 | 查看证明与限制；核心授权不明阻断发布 |
| 隐私 | 账号、联系人、客户材料和凭据不意外露出 | 检查镜头与转场中的遮挡连续性 |
| 文件 | MP4 可从头到尾解码，无截断或损坏 | 完整解码，记录退出状态；不能只读文件头 |
| 规格 | 1080×1920，H.264，yuv420p，30 fps CFR，AAC 48 kHz | ffprobe 与解码验证；特殊规格以任务约定为准 |
| 时间轴 | 画面覆盖全长，无意外空段；音轨与预定尾部一致 | 与 timeline 比较；片长容差原则上不超过 2 帧，编码尾部差异须解释 |
| 画面 | 无缺图、乱码、意外黑帧、失焦、错误比例和拉伸 | 抽检每镜中段、首尾及转场，再完整观看；黑场检测结果需区分设计黑场 |
| 画面增量 | 每个镜头在口播之外提供证据、动作、对比或关系；屏幕文字不逐句复制口播 | 对照 `shots.json` 的 `purpose`、场景 `params` 中的文字与成片；只复读口播的镜头改为证据，或缩短、合并；结果登记为 `av-export` 人工项 `picture.value_add` |
| 操作可读性 | 手机显示下能看清重要按钮、结果和对比 | 手机或近似显示尺寸复核；不只在大屏放大图查看 |
| 字幕 | 文本与实际配音一致，关键名词和数字准确，无越界或遮挡 | 查 JSON/SRT；复核语段起点、长句和专有名词 |
| 字幕时序 | 起止时间合法；代表样本偏差目标不超过约 150 ms | 对照音频复核；工具估计不能替代关键位置试听 |
| 声音 | 无错读、缺字、断尾、意外双声、爆音和刺耳拼接 | 完整试听；没有听到声音时不得填 passed |
| 响度 | 内部目标 -18～-14 LUFS，真峰值 ≤ -1 dBTP | 对最终编码音轨测量；先清楚自然，再满足数值 |
| 配乐 | 不掩盖人声，起止顺畅；音效不过量 | 耳机与普通外放试听；无音乐版本单独标识 |
| 音效对点 | 每个音效对应一个动作标记，起点与动作的接触或状态变化帧相差目标不超过 1 帧（约 33 ms，内部标准）；变速或截短后已重新校准 | 对照时间轴 `sfx` 轨与镜头动作帧逐个抽查并试听；未使用音效的成片按豁免记录 |
| 平台敏感词 | 口播、上屏文字、封面、标题、说明、话题、置顶评论与截图文字不含词表中该平台的 error 词；每张截图都已 OCR 或逐张人工查看 | `script-check terms` 的 `terms-check.json`；`not_checked` 的截图须人工看完才能判 passed。词表是本项目工作清单，通过不代表平台一定放行 |
| 平台风险审核 | 配音稿、脚本、封面文字与发布文案经豆包审核，无未放行的高风险；中风险逐条有结论 | `doubao-review` 的 `doubao-review.json`；放行记录在 `doubao-review.waivers.json`，写明主理人原话。豆包判断只作参考，不代表平台审核结论 |
| 标识 | 生成来源与已有标识被正确处理，发布声明与内容一致 | 检查画面、来源、元数据处理记录与平台声明 |
| 包装 | 封面和标题准确，封面重要文字经实际裁切检查 | 本地布局检查与平台上传预览分别记录 |
| 可复用 | 本地资源齐全，工程数据与成片版本一致 | 在现有授权资源范围内进行一次重渲染验证 |

自动检测应覆盖全片；人工/模型抽帧不能保证发现所有瞬时问题。完整视听检查须记录执行者和文件校验值。没有相应视听能力时保留检查缺项，交付供审核的预览并清楚说明，不能补造检测结果。

## 3. 三类首轮验收任务

### A. 标准任务：真实实操，两个平台

输入：一条确定主题、已授权录屏、可核验资料、固定音色和配乐。

执行：从选题、脚本、配音、字幕、素材索引、Remotion 画面到两版成片全链路运行。

通过：两版分别可播放、时长适配、证据对应、字幕对齐，交付包齐全。每项测试填真实文件路径与校验值，不使用示例截图替代。

### B. 边缘任务：公众号文章，缺少实操素材

输入：一篇较长文章，包含过时产品信息，没有录屏。

执行：重新核验，提取独立主题；能说明原理的部分使用明确的示意画面；核心结论依赖实测时生成补录需求并保持阻塞。

通过：不把文章全文直接朗读，不虚构实测，不隐去缺项；可完成部分继续交付。只有在约定范围内真实产出后才判定对应阶段通过。

### C. 故障与修改任务：中断后继续

输入：已经有音频与预览的项目，修改中间一段含英文工具名与数字的口播，并模拟一次生成任务超时。

执行：只重做改动语段；重算后续偏移；先查询超时任务原 ID 再恢复；复用未改变的已验证资源。

通过：不存在重复扣费请求或音画漂移；费用与任务记录连续；原版本仍可恢复；没有凭据进入日志或 Git。

## 4. 最小链路测试片

在接入计费服务前，用授权的短录音、简单真实录屏、一个流程动画和合法配乐制作约 30 秒测试片。测试片须明显以测试用途命名，不能当成正式自媒体作品。

该步骤确认本地中文字体、媒体解码、配音音轨、字幕、竖屏布局和 MP4 导出可用。通过后再生产真实选题与两平台版本。测试片成功不等于选题、TTS、素材理解或发布链路全部通过。

## 5. 实施记录格式

每次验收记录：任务编号、输入版本、运行环境、执行时间、输出文件、检查项、结果、证据、未通过原因、修复及复测结果。未执行的任务只列在计划中，不填执行时间与通过状态。

当前交付是工作流规范包。音视频链路、工具账号、收费接口、正式音色、实际素材、平台上传预览与流量表现尚未实测。
