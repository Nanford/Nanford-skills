# 阶段2细则：解标分析

> 配套阅读：`references/bid-structure-analysis.md`（招标文件通用6章结构）、`references/mandatory-clause-guide.md`（★条款处理）。
> **先从招标文件识别采购人所属行业/体系**——行业惯例一律以招标文件说明为准；仅当招标方属烟草体系时才参考 `references/tobacco-industry-notes.md`，其他行业不得照搬。

## 目标

把招标文件吃透，输出结构化分析报告。**不解清楚标，绝不动笔写响应文件。**

> 范围裁剪：仅技术部分（technical-only）时仍**全量识别★条款**（技术★遗漏同样废标），评分矩阵重点精读技术分部分。

## 产出（使用 `templates/` 下同名模板）

- `analysis/bid-analysis.md` — 项目信息、关键参数、资质要求、时间节点
- `analysis/scoring-matrix.md` — 评分矩阵：每个评分项的分值、评分标准原文、响应策略、对应文件位置
- `analysis/mandatory-checklist.md` — ★/▲条款逐条清单

## 必须提取的字段

- 项目名称、采购人、代理机构、标包号、预算、**最高限价**
- **投标有效期**、服务/交付/质保期、投标截止时间、开标时间、平台
- 资格要求、联合体/分包规则、禁止情形（须知1.4类条款）
- 签字盖章、上传、文件命名、正副本、格式要求
- 商务/技术/价格/证据类评分项（评分标准**原文**照录——这是阶段5的章节依据和阶段6评标导航表的"编列内容"）
- 强制与否决条款，识别词：`★`、`▲`、`必须`、`应当`、`不得`、`不接受`、`无效投标`、`废标`、`否决`、`实质性响应`、`投标人须`、`承诺`

## 硬性要求

- 评分标准必须**原文照录**，不得改写概括
- ★/强制/否决条款含义无法确定时，停下来问用户（硬停止）
- 投标函有效期天数必须 ≥ 招标文件要求

## 完成标志

**用户确认分析报告内容准确**后，更新状态：

```powershell
python -X utf8 <scripts>\project_status.py "bid-projects\<项目>" --complete 2
```
