# 成品投标文件格式规范

> 提炼自真实中标格式样本：《湖北中烟工业有限责任公司2026-2027年应用系统服务库投标文件》（486页，2026-07-02）。
> 本规范定义最终 `投标响应文件.docx` 的目标形态。招标文件有明确格式要求时，以招标文件为准；本规范补充招标文件未规定的组装与写作惯例。

## 一、总体组装顺序

```
1. 封面          项目名称、招标编号、标包序号、投标人名称、日期
2. 资格审查导航表
3. 符合性审查导航表
4. 评标导航表
5. 目录          带页码，Word自动生成
6. 一、商务文件   十二件套（见第三节）
7. 二、技术文件   技术描述 + 各服务/技术方案（见第四节）
```

**页面规范**：
- 页眉：`<项目全称>投标文件`，每页出现
- 页码：全文连续编号，目录、导航表页码与正文实际页码一致
- 每份独立商务文件末尾落款三行：
  ```
  投 标 人：XXX有限公司（盖单位公章）
  法定代表人或授权代表：       （签章）
  YYYY 年 MM 月 DD 日
  ```

## 二、三张导航表（评标专家友好设计 + 自查工具）

放在封面之后、目录之前。作用：让资格审查、符合性审查、评分的每一项都能被评委在3秒内定位到页码；同时是投标人交付前的自查清单。

### 2.1 资格审查导航表

| 序号 | 投标人资格要求 | 须提供的资料 | 投标文件对应页码 |
|---|---|---|---|
| 1 | （招标公告资格要求**原文照抄**） | （招标文件要求的证明材料原文） | P__ |

要点：
- 资格要求逐条对应，不合并、不改写
- 由招标代理机构负责查询的项（如禁入名单、部分信用查询），页码栏填 `——` 并注明"投标人无需提供"
- 涉及多页材料时写页码范围，如 `P67-79`

### 2.2 符合性审查导航表

| 序号 | 审核内容 | 须查验的资料 | 投标文件对应页码 |
|---|---|---|---|
| 1 | （符合性审查表条目**原文照抄**） | （指向具体文件，如"一、商务文件（二）投标一览表"） | P__ |

常见条目：保证金按要求提交、按规定签章盖公章（页码范围=全文，如 `P1-486`）、报价唯一且不超限价、投标有效期满足规定、无否决情形、无异常低价情形。

### 2.3 评标导航表

| 评标项目 | 评标分项 | 分值 | 编列内容 | 自查情况 | 投标文件对应页码 |
|---|---|---|---|---|---|
| 价格部分 | XX价格 | 20分 | （评分标准**原文照抄**，含基准价公式） | 符合 | P__ |
| 商务部分 | 体系认证 | 4分 | （原文） | 符合 | P__ |
| 技术部分 | XX服务方案 | 14分 | （原文，含方案应包含的内容清单） | 符合 | P__ |

表尾备注：`请与第三章 评标办法 详细评审表保持一致。`

要点：
- "编列内容"列**原文照抄**评分标准全文（含公式、注释、证明材料要求），不概括
- "自查情况"填"符合"，交付前逐行确认
- 评标项目按 价格部分 → 商务部分 → 技术部分 分组

### 2.4 页码回填规则

Markdown 中间稿阶段页码填占位符 `P__`，同时在括号内标注章节位置（如"一、商务文件（十）"）便于定位。最终 DOCX 分页定稿后，在 Word 中回填真实页码。**页码未回填不得交付。**

## 三、商务文件十二件套（顺序与内容要点）

| 序号 | 文件 | 内容要点 |
|---|---|---|
| （一） | 投标函 | 官方模板原文，只填空白。含有效期承诺、保证金已交声明、中标后签合同/廉洁协议/保密协议承诺、保密承诺（通常5年）。落款签章 |
| （二） | 投标一览表 | 项目名称、招标编号、标包序号、货币；各标的报价（注明不含税/含税）、税率；表下注明限价说明。落款签章 |
| （三） | 商务响应偏离表 | 列：序号/条目号/招标文件的采购需求或合同条款/投标文件的响应情况/说明。逐条"无偏离"；有偏离的列明内容并注明正/负偏离。**无空项**。落款签章 |
| （四） | 法定代表人身份证明 | 投标人、单位性质、地址、成立时间、经营期限；法人姓名/性别/年龄/职务；附身份证正反面。信息必须与营业执照一致 |
| （五） | 法人授权委托书 | 授权代表姓名、职务、权限范围、授权期限（≥投标有效期）；附授权代表身份证 |
| （六） | 廉洁自律承诺书 | **招标文件原文照抄，一字不改**，落款签章 |
| （七） | 投标保证金 | 三件套：①银行汇款凭证 ②基本存款账户信息（开户许可证/基本存款账户信息表）扫描件 ③已开立银行结算账户清单。保证金必须从基本户转出，账户信息前后一致 |
| （八） | 资格审查资料 | ①投标人基本情况表（含主要负责人/实控人及身份证号、关联企业——对应串标审查）②营业执照 ③投标人信誉声明 ④资格要求响应承诺书、须知1.4承诺书 ⑤非联合体投标声明书 ⑥信用查询截图（按招标文件分工，见3.1）⑦特殊资格要求证明（如指定类型业绩，按业绩五件套提供） |
| （九） | 近年财务状况 | 按招标要求年份（通常近3年）的完整审计报告扫描件 |
| （十） | 类似业绩证明 | 每项业绩五件套（见3.2）。数量按评分标准上限配置（如每项3分、最多12分则配4-6项留余量）。合同签订时间必须落在招标要求窗口内 |
| （十一） | 项目管理机构及人员 | ①拟委任人员资历表（逐人）②每人三件套：毕业证及身份证复印件、资格证书复印件（PMP/软考等）、社保证明材料复印件 ③团队成员具备类似项目业绩的合同复印件（对应"团队成员有类似业绩"评分项） |
| （十二） | 其他商务材料 | ①体系认证证书+官方平台查询截图（见3.3）②纳税信用等级证明+税务局查询截图 ③招标文件要求的其他资料 ④需加以说明的承诺书（对采购需求商务要求、★技术标准、否决情形等的专项响应承诺书）⑤其他加分资质（CMMI、高新技术企业、AAA信用、专精特新、ISO14001/45001等） |

### 3.1 信用查询五平台

| 平台 | 网址 | 查什么 |
|---|---|---|
| 国家企业信用信息公示系统 | gsxt.gov.cn | 严重违法失信企业名单 |
| 信用中国 | creditchina.gov.cn | 重大税收违法、严重失信主体 |
| 中国执行信息公开网 | zxgk.court.gov.cn | 失信被执行人（含法人/主要负责人） |
| 中国裁判文书网 | wenshu.court.gov.cn | 行贿行为记录 |
| 天眼查 | tianyancha.com | 控股、管理关系（串标审查） |

注意：招标文件可能约定部分平台由**招标代理机构**负责查询，投标人无需提供截图——导航表中对应页码填 `——`。截图须体现查询时间和查询条件。

### 3.2 业绩五件套

每项业绩必须齐全：
1. **合同关键页扫描件** — 至少含：合同名称页、采购内容页、合同金额页、签字盖章页、签署时间页
2. **发票扫描件** — 至少一张对应发票
3. **发票查验截图** — 国家税务总局全国增值税发票查验平台（inv-veri.chinatax.gov.cn）查询验证截图
4. **银行收款凭证** — 至少一张对应转账/收款凭证
5. **其他说明文件** — 验收证明、合同金额与发票差异说明等（如有）

资料不全 = 该业绩不予认可。

### 3.3 证书 + 官方查询截图配对

| 证书 | 查询平台 |
|---|---|
| ISO9001 / ISO20000 / ISO27001 等认证 | 全国认证认可信息公共服务平台 cx.cnca.cn |
| ITSS | itss.cn |
| 纳税信用等级 | 税务局官网查询截图或税务局盖章版证明（须体现评价年度） |

**证明不全或不提供 = 不得分**，只放证书不放截图等于白放。

## 四、技术文件写作模式

### 4.1 结构

```
二、技术文件
（一）技术性能、参数的详细描述
    1. 公司简介与履约能力（简介/建设优势/技术能力优势/运维与服务优势）
    2. 对采购人现状的技术理解、技术架构适配能力
（二）服务方案 / 技术方案（按评分表逐个评分项设方案）
    每个方案 = 招标需求响应总述 → 方案正文 → 服务承诺
```

**章节结构 = 评分标准"编列内容"列出的方案要求。** 例如评分标准写"方案包括：(1)系统交维与下线 (2)维护与故障处理 (3)系统监控与巡检 (4)应用安全管理 (5)优化改进与支持 (6)人员管理及保障"，方案正文就设这六章，顺序一致，各子项（故障处理、配置管理、数据维护、权限管理……）设专门小节。

### 4.2 招标需求响应总述（每个方案的第一节）

写法固定为"引原文 + 表响应"两段式，逐条覆盖：

1. 开头声明：`我方已逐条研读招标文件"XXX"全部内容，确认所有条款均为实质性响应要求。以下逐条分析招标需求并说明我方响应方案，确保关键参数、专有名词、技术标准与招标文件完全一致，无任何负偏离。`
2. 每个需求条目：先原文复述招标需求（规模数字、金额限制、服务范围等**一字不差**），再写`我方已充分理解……我方方案中「X章节」覆盖……`，用「」标注呼应的章节名
3. 需求中的模糊项（如"SLA以二次采购为准"）：给出建议标准，同时明确标注"具体以XX为准"

### 4.3 方案正文

- 深层级编号：1.1.1.1 级别，让每个评分子项都有独立小节可指（1.1.1 以下用整行加粗，不占标题层级）
- **成段论述，禁止碎片列表**：每小节正文为完整段落（定位/原因 → 机制/流程 → 量化承诺），每个大节先写引言段；单个方案成稿30页以上（详见 `technical-proposal-writing.md`）
- 内容具体化：范围、流程步骤、工具/技术栈、角色职责、审批点、记录表单、里程碑、交付物、升级路径、回滚方法、验收依据
- 量化指标显性化：故障分级SLA（响应/恢复时间）、系统可用率、巡检频次（日/周/月）、监控指标体系、KPI考核维度
- 方法论命名化：如"4A架构方法论"、"三级计划体系"、"PDCA持续改进"、"AB角机制"，便于评委记忆和给分

### 4.4 服务承诺（每个方案的最后一节）

信函式，抬头致招标人和代理机构，引用项目名称和招标编号，随后编号列出量化承诺：
- 驻场团队人数与覆盖地域
- 7×24支持渠道（热线/Email/企业微信/VPN远程）
- 系统可用率（如≥99.9%月度统计）、分级故障响应/恢复时限
- 遵守采购人管理制度、网络安全法、等保2.0，数据"最小必要"访问、不外传
- 免费开发服务额度（如≤当期合同金额10%）
- 项目经理稳定性（服务满N月、更换提前30天通知）
- 知识产权归属招标人
- 落款：投标人名称 + 日期

## 五、分页与版式规则（中标样本逐页核实）

**分页规律（样本第1-40页逐页验证）**：
- 封面、三张导航表、目录各自独立起页
- **商务文件每一个章节、小节独立起页**：（一）～（十三）逐项起页；项内的每份证明材料（银行汇款凭证、营业执照、信誉声明、每张证书、每张查询截图、业绩的合同/发票/查验截图/凭证）也各占一页，标题在页顶、下方留空放扫描件
- **紧跟父级标题的第一个子标题与父级同页**：样本第21页"一、商务文件"+"（一）投标函"同页、第34页"（八）资格审查资料"+"1.投标人基本情况表"同页
- 技术方案正文（三/四级标题以下）连排不分页，只有方案级标题起新页

**版式要素**：
- A4纵向；页眉居中放`<项目全称>投标文件`（小五）；页脚居中页码域，全文连续
- 封面：信息行（项目名称/标包名称/招标编号）三号居中，"投　标　文　件"小初加粗居中，投标人/日期三号居中
- 目录用 Word TOC 域（标题样式1-3级），DOCX 定稿分页后在 Word 中更新域生成页码
- 标题编号写在标题文本内（一、/（一）/1./1.1），不叠加 Word 自动编号
- 已有扫描件用图片直接插入（居中、按可打印区域缩放）；暂缺的写"（此处附：XXX扫描件）"留空占位

**组装标记**（写入 Markdown，`build_response_docx.py` 识别）：`<!-- cover -->` 封面 / `<!-- toc -->` 目录域 / `<!-- notoc -->` 标题不进目录 / `<!-- break-all-headings -->` 全节独立起页（商务文件用）/ `<!-- pagebreak -->` 强制分页。

## 六、交付前格式自查

- [ ] 组装顺序符合第一节；封面信息与招标文件一致
- [ ] 三张导航表齐全，"编列内容"与评标办法原文一致，页码已回填
- [ ] 目录域已在 Word 中更新，页码与正文一致
- [ ] 页眉项目名、页脚页码全文连续
- [ ] 商务文件每章节/小节/每份证明材料独立起页
- [ ] 每份商务文件落款签章行齐全
- [ ] 五件套/三件套完整，证书配查询截图（图片已插入或留空页占位）
- [ ] 技术方案每个评分项有对应章节，每个方案有响应总述和服务承诺
- [ ] `validate_docx_format.py` 校验通过
