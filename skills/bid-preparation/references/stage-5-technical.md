# 阶段5细则：编制技术文件

> 配套阅读（写作前必读）：**`references/technical-proposal-writing.md`**、`references/scoring-patterns.md`、`references/industry-common-terms.md`、**`templates/技术方案大纲示例.md`**。
> 取材规则：技术方案正文取自 `company-library/technical/产品资料/`——先读该目录 `README.md` 认定的 1~2 份**主资料**做骨架，其余按需加载。
> **响应样本**：阶段1已提取的用户响应样本（`extracted-text/` 中 response-samples）必须在列大纲与写正文时对照——学其**章节完整度、详略、项目管理/实施模块**，不抄其公司事实与数字。
> **硬门禁**：必须先输出技术大纲并经用户确认，再**按大纲一级章节逐章**编制；每章经用户确认后再写下一章。禁止一次灌完整技术方案。

## 目标

按评分表顺序组织、针对评分标准写作，拿到最高技术分；内容深度对齐采购需求与响应样本。

## 核心原则（大纲由"采购需求"和"评分表"共同决定）

> **内容骨架 = 采购需求/技术要求清单**：招标文件列了哪些设备、技术要求、服务事项，方案就必须逐条有实质内容。
> **组织与详略 = 评分标准"编列内容"**：章节切分、顺序、篇幅向评分点靠拢。
> **模块完整度 = 响应样本 + 必含模块**：样本有的管理/实施专章不要丢；且**无论样本如何，必须覆盖项目管理/实施方案**（见下）。
> 章节顺序**不照抄**招标文件正文目录，按上面规则重排。

## 步骤A：技术写作大纲（先做，等确认）

**前置 P0/P1**：

- `project-profile.md` 已确认类型；按 `project-type-routing.md` 选骨架
- `format-clone-checklist.md` 技术相关行无「缺口」
- `mandatory-checklist` 已列出全部★；大纲章节须能承接三角中的「正文位置」
- `material-gate`：若 `outline_only`，只交大纲+技术资料缺口清单，**禁止**写成套伪详细方案
- `scoring-strategy.md` 主观分项已映射到大纲章节
- 多现场 → 大纲含分现场实施；施工/安装 → 大纲含安全环保；硬件标 → 大纲以参数/安装调试为主
- 类型骨架：`service_ops`→`technical-proposal-writing.md`；`hybrid_retrofit`→`sample-hybrid-retrofit.md`；`hardware_supply`→`sample-hardware-supply.md`
- 建议维护 `requirement-index.md`（采购需求编号），便于 P2 覆盖率统计

1. 输出 `analysis/technical-writing-outline.md`（参照 `templates/技术方案大纲示例.md`，**按类型裁剪**），表格至少含：
   - 方案章节（大纲一级条目，即后续「逐章确认」的粒度）
   - 覆盖的采购需求条目
   - 对应评分点
   - 内容取材（产品资料/样本对照点）
   - 预估篇幅
   - **是否覆盖项目管理/实施方案**（是/专章名/不适用+依据）
2. **必检**：大纲中是否出现独立的「项目管理方案」「实施方案/施工方案/实施计划」「进度计划」类章节；若招标文件与评分表均明确不要求，写「不适用」及条款出处，否则必须列入。
3. **向用户展示大纲，明确请求确认**。未获确认前禁止写 `output/技术文件/*` 正文（技术响应偏离表也不例外——可先作为大纲第一项，确认大纲后再写）。
4. 用户确认后：
```powershell
python -X utf8 <scripts>\project_status.py "bid-projects\<项目>" --confirm-outline technical
```

## 步骤B：按大纲逐章编制（一章一确认）

对大纲一级章节按序：

1. 只写当前一章到 `output/技术文件/`（可多文件，但本轮只交付本章）
2. 汇报：路径、对应评分点、量化承诺要点、待补图/表
3. 请用户确认；确认后：
```powershell
python -X utf8 <scripts>\project_status.py "bid-projects\<项目>" --confirm-section technical --section "章节名"
```
4. 再写下一章。禁止跳章；改大纲须先更新大纲文件并重新确认。

## 写作模式（成品样本验证有效）

1. **技术响应偏离表**：从采购需求/技术要求逐条提取，保留条款编号，★条款标"完全满足"，逐条注明证明材料位置，无空项
2. **每个方案开头设"采购需求响应总述"**：先归纳采购需求涉及的目标、原则、技术领域和关键参数，再给出总体响应结论与本章展开范围。不得写采购文件章号、节号、条款号或"对应采购需求X.X"，不得用章节对应代替实质内容
3. **方案正文**：章节与评分标准逐块对应；内容 = 采购需求 × 公司产品资料 × 样本详略；落到真实设备、参数、流程、角色、里程碑、验收
4. **项目管理方案 + 实施方案（强制关注）**：
   - 项目管理：组织架构、职责、沟通、进度、风险变更、质量、文档
   - 实施方案/施工方案：分阶段步骤、资源现场、安全、验收移交（类型适配：工程/IT/运维）
   - 进度计划：阶段表 + 里程碑
5. **每个方案结尾附"服务承诺"**：信函式，量化指标，落款签章（`templates/服务承诺书.md`）
6. **架构图**：涉及系统架构时生成SVG，组件名称与招标要求一致
7. **实施计划、团队配置、培训、售后**：对应评分项设专章

## 深度与文风底线（强制标准）

- **成段论述，禁止碎片列表**：每个小节正文是完整段落（3句以上）。禁止一行一条的清单碎片
- **每个大节先写引言段**，再展开小节
- **量化到数字**：时限、指标、频率、人数、周期——没有数字的承诺不得分
- **篇幅基准**：单个服务方案成稿30页以上（有样本时按样本量级靠拢）；深于五级标题的小节题用整行加粗（`**1.3.1.1.1 交接准备阶段**`）
- **表格只用于**：SLA、KPI、评分权重、风险矩阵、进度计划表
- 技术方案正文连排不分页（不加 `<!-- break-all-headings -->`）

## 中间稿格式（防 Markdown 泄漏）

- 禁止：行内反引号、`---`、`- 列表` 当正文、`> 引用`、`[文字](url)`
- 列举用「（1）（2）（3）」且每项多句论述
- 允许：`#` 标题、Markdown 表格、`![图](路径)`、整行 `**小节题**`

## ★三角回填

每写完含★响应的章节或技术偏离表，立即更新 `mandatory-checklist` 的「偏离表位置」「正文/方案位置」，状态改为已响应（或缺材料）。
