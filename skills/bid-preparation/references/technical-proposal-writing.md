# 技术方案写作模式（中标样本技术部分提炼）

> 来源：湖北中烟2026-2027年应用系统服务库中标投标文件技术部分（第403-486页，共83页）逐节分析。
> 使用阶段：阶段5编制技术文件。写方案前先读本文件，按这里的骨架和文风写，不要自创结构。

> **为什么禁「`**引导词：**` 一句话」文风**（SKILL.md 中间稿禁令的展开）：
> ① 它是**伪装成段落的碎片清单**——每条只有一句话，评标专家看到的是罗列而非论述，章内深度分拿不到；
> `check_content_quality.py` 会按「引导词式碎片文风」告警。
> ② `**` 只有本 Skill 的组装脚本会消化。中间稿被直接粘进 Word、发给同事、或交给别的工具时，
> 星号会原样漏出成 `**保密承诺：**`。
> 正确写法二选一：**提升为独立小节题**（`**1.1.1 保密承诺**` 后另起一段展开），
> 或**并入成段论述**（「（1）保密承诺方面，我方……」）。

## 一、总体结构（技术文件三大块）

```
二、技术文件
├── 技术响应偏离表（★条款逐条，无空项）
├── （一）技术性能、参数的详细描述        ← 约4页
│   ├── 1. 公司简介（履约能力证明）
│   │   ├── 1.1 公司简介（成立背景、主营产品、服务理念）
│   │   ├── 1.2 建设优势（面向本项目业务领域的能力论述）
│   │   ├── 1.3 技术能力优势（认证体系、方法论、开发平台工具链）
│   │   └── 1.4 项目运维优势（售后团队、响应体系、服务内容全景）
│   └── 2. 详细说明技术性能、参数
│       ├── 2.1 对招标人系统现状的技术理解（用招标文件里的规模数字说话）
│       └── 2.2 技术架构适配能力（逐维度：云环境/微服务/传统架构/集成平台/信创/数据标准）
└── （二）服务方案                        ← 每个方案30-40页
    ├── 1. XX服务方案（按评分表"编列内容"分块）
    └── 2. YY服务方案
```

## 二、单个服务方案的十节骨架（样本验证的得分结构）

以服务型运维方案为例（样本41页），每个方案按此骨架展开：

| 节 | 内容 | 得分作用 |
|---|---|---|
| x.1 招标需求响应总述 | 归纳需求目标、原则、技术领域与关键参数→明确总体响应→列明本方案展开内容；不写采购文件章节号或条款号 | 让专家直接看到需求理解、响应范围和实现方向 |
| x.2 项目理解与总体思路 | 招标人现状调研 + N大挑战识别 + 应对理念 + 技术环境适配维度 | 证明"懂客户"，区分度最高的一节 |
| x.3~x.7 核心方案主体 | 严格按评分标准"编列内容"列出的领域逐块展开（如：交维与下线/维护与故障处理/监控与巡检/安全管理/优化改进） | 评分主体，每块对应评分子项 |
| x.8 人员管理及保障 | 组织架构（三级）、人员配置（数字）、考核、稳定性承诺 | 对应团队类评分项 |
| x.9 评估与改进 | 质量评估体系、KPI指标、月报/季评/年度总结、PDCA | 对应服务管理类评分项 |
| x.10 服务承诺 | 信函式，致招标人+代理机构抬头，8-9条量化承诺，落款盖章 | 收尾定调，量化指标可被引用打分 |

开发建设类方案的主体节按生命周期展开：需求调研与分析 → 系统设计（按4A：业务/数据/应用/技术/安全架构逐一设计）→ 开发测试 → 上线验收 → 售后质保 → **项目管理配套（组织/沟通/风险/变更/进度）** → **实施方案（分阶段实施/割接上线）** → 服务承诺。

### 响应总述的内容化表达

响应总述先概括采购需求的实质内容，再说明我方的设计响应和展开范围。领域名称、参数、系统规模和专有名词必须来自本项目采购需求，不得把其他项目示例直接套入正文。

禁止写：`本节对照采购文件第四章《采购需求》第2.1节项目总体要求、第2.4节建设原则、第2.7节技术要求。`

IT 建设类示例：`我司已全面研读采购需求，并围绕项目总体目标、建设原则和技术要求形成系统化设计响应。方案从建设原则、技术架构、集成开放、部署方式、性能保障、安全体系、二维码改造技术要点及开发规范等方面逐项展开，明确相应的实现机制、技术措施、实施路径与验收依据。`

## 二补充、项目管理与实施方案（技术文件必含模块）

> 一般项目都需要项目管理或实施（施工）方案。**技术大纲必须单列**；正文须成段论述，不得只用三五行带过。除非招标文件与评分表均明确不要求，并在大纲注明「不适用」及依据。

### 项目管理方案（建议独立成章或作为大节）

| 小节 | 应写清的内容 |
|---|---|
| 组织架构 | 项目决策层/管理层/执行层；与招标人接口人；RACI 或职责表 |
| 沟通与汇报 | 日报/周报/月报、会议机制、升级路径、问题闭环 |
| 进度与里程碑 | 阶段划分、关键节点、延误预警与赶工措施 |
| 风险与变更 | 风险识别—评估—应对—跟踪；变更申请—评审—发布 |
| 质量与文档 | 质控点、评审、配置与文档交付清单 |
| 资源保障 | 人员稳定、备件/工具、分包（若允许）管理 |

### 实施方案 / 施工方案（按项目类型选型）

| 类型 | 展开要点 |
|---|---|
| 工程/现场施工 | 施工组织、工序、安全文明、进度、材料机具、验收移交 |
| IT 建设/集成 | 调研→设计→开发测试→部署割接→试运行→验收→移交 |
| 运维/维保 | 交接进场→日常运维→专项维保窗口→应急→持续改进 |
| 服务类 | 启动→服务交付节奏→SLA 执行→考核改进→期满移交 |

每类均须：**分阶段步骤（可执行）+ 资源与前置条件 + 安全/合规 + 验收与移交标准**。有用户响应样本时，对照样本同类章节的篇幅与小节粒度。

### 进度计划

至少一张阶段/里程碑表（阶段、主要工作、工期/节点、责任角色、交付物、评审点），正文用段落说明关键路径与并行关系。

## 三、文风规则（"像标书"和"像清单"的分界线）

1. **成段论述**：每个小节正文是完整段落，模式为"定位/原因 → 机制/流程 → 量化承诺"。
   - ❌ 碎片清单：`2.1.1 交接启动：中选通知书发出后，我方立即启动交接准备。`
   - ✅ 成段论述：`运维服务交接是将系统从建设方顺利过渡到我方运维团队的关键环节。依据招标文件中"中标人可提前开展运维服务交接工作"的要求，我方将在中选通知书发出后3个工作日内成立交接工作组，由项目经理担任组长……交接计划经招标人审批后作为交接工作的执行基线。`
2. **每个大节先写引言段**：一段话总述本节定位与价值，再进小节。
3. **段内列举**用"（1）（2）（3）"或"第一/第二/第三"或"挑战一/挑战二"，每项都是完整多句论述，不是短语。
4. **量化到数字**：没有数字的承诺不得分。时限（3个工作日/30分钟内回滚）、指标（可用率≥99.9%、P50/P95/P99）、阈值（CPU≥85%告警）、人数（驻场≥12人）、周期（每季度权限审计、每月备份演练）、留存（日志在线30天/归档2年）。
5. **呼应招标原文**：关键参数、系统规模、专有名词与招标文件完全一致（如"140套自建系统、40套统建系统、4000余个接口"），并在响应总述中直接写入这些需求内容，不写其来源章节号。
6. **表格只用于天然表格化内容**：SLA分级表（等级/定义/响应时限/恢复目标/通知方式/升级时限）、KPI指标、评分权重、风险矩阵。正文不得表格化。
7. **标题层级**：方案主节用 1. / 1.1（Word 标题3/4级），更深的 1.1.1 和 1.1.1.1 用整行加粗段落（`**1.1.1 标题**`），保持目录清爽。
8. **成品语言**：`我方承诺…`、`本项目实施范围包括…`、`服务响应机制如下…`；禁止出现写作过程语言。
9. **内容取材**：方案正文由「采购需求条目 × 公司产品资料」生成，落到真实设备/参数/做法。
10. **正文禁止来源定位**：正文不写"详见第X章"、"见前述"、"对应采购需求X.X.X"或采购文件章/节/条款号；直接写需求内容与响应措施。编号只进入偏离表、需求索引、强制条款清单、写作大纲和证明材料导航。
11. **禁止 Markdown 泄漏**：中间稿不用反引号、`---`、`- 列表` 当正文、`> 引用`；列举用（1）（2）成段。
12. **对照响应样本写深度**：有用户样本时，项目管理/实施/SLA 等章节的小节粒度与篇幅向样本靠拢，不抄数字与事实。

## 四、服务承诺节的固定写法

```
致：<招标人全称>、<代理机构全称>

我司在参与贵司<项目名称>（招标编号：XXX）项目投标活动中，
我司对<方案对应服务>做出如下郑重承诺：

1. <团队规模承诺，具体人数与覆盖地域>
2. <支持渠道承诺，7×24小时+渠道列举，与招标文件列举方式一致>
3. <SLA承诺，逐级列出响应/恢复时限，与方案正文SLA表一致>
4. <制度遵从承诺，点名招标人管理制度名称>
5. <安全合规承诺，点名法律法规和招标人安全责任书>
6. <免费服务额度承诺，公式与招标文件完全一致>
7. <人员稳定承诺，项目经理服务时长+更换通知期>
8. <知识产权归属承诺>
9. <应急保障承诺>

投标人名称：XXX（盖单位公章）
日期：XXXX年XX月XX日
```

## 五、篇幅基准与自检

- 单个服务方案成稿 **30页以上**（样本：41页/38页）；响应总述2-5页、项目理解2-3页、每个核心领域节3-6页
- 自检清单：
  - [ ] 评分标准"编列内容"每一块都有对应章节
  - [ ] 每节开头有引言段
  - [ ] 无一行一条的碎片清单段
  - [ ] 每节至少一组量化承诺数字
  - [ ] 招标文件的规模数字/专有名词在方案中出现且一致
  - [ ] 方案正文未出现采购文件章号、节号、条款号或"对应采购需求X.X"
  - [ ] 方案结尾有信函式服务承诺并落款
  - [ ] 含项目管理方案与实施方案/进度计划（或大纲注明不适用）
  - [ ] 无 Markdown 泄漏痕迹
