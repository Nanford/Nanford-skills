# ★和▲条款处理指南

## 标记含义

| 标记 | 含义 | 不满足的后果 | 处理策略 |
|------|------|-------------|----------|
| **★** | 实质性要求（强制条款） | **废标**（投标无效） | 必须100%满足，逐条提供证明 |
| **▲** | 重要技术要求（加分项） | 不扣分但丢分 | 尽量满足，提供超越标准的说明 |
| 无标记 | 一般性要求 | 可能扣分 | 保持"无偏离" |

## ★条款特征

★条款通常出现在：
- 第四章采购需求/技术规范中
- 标示为"★"或"★号条款"
- 招标文件第二章前附表会有"★号条款定义及处理"说明
- 评标办法中通常会有"★条款响应情况表"

## ★条款常见类型

### 技术类★条款
```
例1: ★技术兼容性：系统须支持Windows Server 2012及以上操作系统
例2: ★项目进度：合同签订后90个工作日内完成开发并具备上线条件
例3: ★人员要求：项目团队须含1名项目经理，提供PMP证书及6个月社保证明
例4: ★信息安全：须满足等保二级要求
例5: ★付款方式：不接受偏离
```

### 商务类★条款
```
例1: ★投标有效期：不少于90天
例2: ★投标保证金：按要求金额和形式缴纳
例3: ★最高限价：投标报价不得超过XXX万元
例4: ★资质条件：须具备XX资质
例5: ★不接受联合体
```

## ★条款响应方法

### 1. 在投标文件中标注
对于每条★条款，在响应文件中：
- 使用**加粗**或特殊标记标注
- 明确写明"完全满足"
- 提供证明材料或出具承诺函

### 2. 建立★条款响应对照表
在投标文件中可增加一个专门的"★条款响应一览表"：
```markdown
| 序号 | ★条款内容 | 出处 | 响应说明 | 证明文件 |
|------|-----------|------|----------|----------|
| 1 | 支持Windows Server 2012以上 | 第四章4.7.1 | 完全满足，支持至Windows Server 2022 | 技术方案§2.3 |
```

### 3. 承诺函
对于要求以承诺函形式响应的★条款：
- 使用"我司承诺……"的明确措辞
- 不得使用"应该""可以""尽量"等模糊词语
- 加盖公章

## ▲条款响应方法

▲条款是加分的关键：
1. 不仅要满足，还要**详细说明**如何满足
2. 如果有超越标准的地方，**重点突出**
3. 每个▲条款在技术方案中**独立一节**

## 常见陷阱

| 陷阱 | 说明 | 避免方法 |
|------|------|----------|
| 隐含的★条款 | 前附表中用加粗或下划线标示但未标★的条款 | 仔细阅读前附表，加粗项同等对待 |
| ★条款理解偏差 | 对"支持""兼容"等词语的理解与招标人不同 | 不确定时提交澄清问题 |
| 承诺函措辞不当 | "将尽力""尽可能"等模糊表述 | 使用"承诺""保证""确保" |
| 缺少证明材料 | 只说满足但不提供证据 | ★条款必须附带证明材料 |
